## 1. 해결하려는 실무 문제

생성형 AI로 문장 번역은 쉬워졌지만, 실제 영상 자막과 청각장애인용 SDH(Subtitles for the Deaf and Hard of Hearing) 자막은 여전히 사람이 한 줄씩 다시 손봐야 납품할 수 있습니다.

범용 LLM이 자막에서 실패하는 세 가지:

1. **글자 수·읽기 속도 규정 위반**
   - 자막은 화면을 가리지 않도록 줄당 글자 수와 줄 수가 정해져 있고, 시청자가 읽을 수 있게 초당 글자 수(CPS) 상한이 있습니다.
   - 예: 넷플릭스 한국어 규정은 **줄당 16자·최대 2줄**, 읽기 속도 **번역 자막 12자/초, SDH 14자/초**입니다(저장소 `rules/learned/netflix/ko-*.yaml` 머리말).
   - 발주처마다 값이 다릅니다(예: 줄당 14자로 조이는 발주처). 범용 LLM은 이 값을 모르고 문장을 늘여 씁니다.
2. **타임코드(TC) 인점·아웃점 오류**
   - 대사가 끝났는데 자막이 남아 있거나, 화면 전환(Shot Change)을 넘어가 시청 피로를 줍니다.
3. **고유명사·맥락 오류**
   - 인명·브랜드·작품명·신조어의 표기를 지어내거나 번역투로 옮깁니다.

숙련 번역가는 "어떤 조사를 빼야 16자 안에 뜻이 남는지", "인점은 말소리보다 2~3프레임 앞, 아웃점은 말끝보다 6~9프레임 뒤, 화면 전환 앞뒤 0.5초는 피한다" 같은 판단을 감각(암묵지)으로 합니다. 이 프로젝트는 그 검수 규범을 규칙 파일과 에이전트로 옮깁니다.

## 2. 에이전트 구조

현업 작업 순서를 그대로 따릅니다. **TC를 먼저 잡아 확정하고 잠근 뒤**, 그 틀 안에서 자막 문장을 만들고 고칩니다.

- **A. TC 작업** — 전사 없이 소리만 보고 인점·아웃점을 잡아 확정·잠금
- **B. 자막 작업** — 잠긴 TC 안에서 전사·번역·줄바꿈을 하고, **판정(Judge) → 교정(Refine)을 되풀이하는 자가교정 루프**로 다듬음. 고유명사 확인에 **Liner Search API·MCP** 사용

역할 나눔:
- **숫자로 판정할 수 있는 것(인·아웃점, 글자 수, CPS)은 규칙 코드**가 맡습니다. LLM이 "대충 맞다"고 넘기지 않습니다.
- **LLM은 문장 압축·의역**만 맡습니다. TC는 건드리지 않습니다.
- **라이너는 고유명사 표기 확인**만 맡습니다.

### A. TC 작업 — 인점·아웃점을 잡는 법

번역가가 파형을 보며 손으로 찍던 인·아웃점을, 소리 신호와 발주처 규정으로 계산합니다.

```
[영상/오디오]
       ↓
[A-1: 말소리 구간 검출]
  - 전사 없이 오디오만으로 말소리가 시작·끝나는 경계를 찾음 (Silero VAD)
  - 배경음악·효과음이 큰 장면은 대사 성분을 먼저 분리해 경계를 또렷하게 함
       ↓
[A-2: 발주처 규정 여유 적용 (규칙 코드)]
  - 인점: 말소리 시작보다 2~3프레임 앞
  - 아웃점: 말끝보다 6~9프레임 뒤
  - 앞 자막 아웃점과 다음 자막 인점이 겹치면 인점 우선
  - 최소·최대 표시 시간 지키기
  - 여유값은 코드에 박지 않고 발주처 규정 파일에서 읽음
       ↓
[A-3: 화면 전환 (SDH 작업만)]
  - 화면 전환을 검출해, 전환 앞뒤 0.5초 안에 걸친 인·아웃점을 전환 지점에 맞춤
  - 우선순위: 인점 > 화면 전환 > 아웃점
       ↓
[A-4: 자동 확정과 잠금]
  - 말소리 경계 + 규정 여유와의 오차가 0.04초 미만(1프레임 안팎)이라고 판정된 구간만 자동 확정
  - 확신이 낮은 구간은 "사람 확인" 카드로 넘김 (파형 위치·이유 표시)
  - 확정한 TC는 잠금 — 이후 단계는 TC를 움직이지 않음
```

### B. 자막 작업 — 자가교정 루프

```
[잠긴 TC + (있으면) 원어 대본]
       ↓ 전사(faster-whisper) → 대본 대조 → 번역(번역 작업만) → 줄바꿈
[B-1: 판정 (규칙 코드, 결정론적)]
  - 차원 1: 글자 수 (줄당 상한·줄 수, 발주처 규정 파일 값)
  - 차원 2: 읽기 속도 (잠긴 TC의 표시 시간 대비 CPS 상한)
  - 차원 3: 고유명사 후보 표시 (검증이 필요한 낱말만 골라냄)
       ↓
       ├─ [위반 0건] ──→ [최종 SRT/VTT 출력]
       └─ [위반 있음]
              ↓
[B-2: 고유명사 확인 (Liner Search API·MCP)]
  - 차원 3이 고른 낱말만 검색해 공식 표기를 출처와 함께 확인
  - 대사 문장 전체는 보내지 않음 (원고 유출 방지, 아래 3절)
              ↓
[B-3: 교정]
  - LLM이 위반한 자막의 문장만 뜻을 살려 압축·의역 (TC는 그대로)
              ↓
[B-1로 돌아가 다시 판정 — 최대 3회]
  - 3회 뒤에도 남은 위반은 억지로 고치지 않고 "사람 확인" 카드로 넘김
    (위반 규칙 ID·자막 번호·이유 표시)
```

TC가 잠겨 있으므로, 읽기 속도를 넘기면 **TC를 늘리지 않고 문장을 줄여서** 맞춥니다. 현업 번역가가 하는 방식 그대로입니다.

## 3. 라이너 API 접목 방안

- **Liner Search MCP**
  - 이 저장소의 에이전트 루프에 라이너 원격 MCP 서버를 도구로 등록합니다.
  - 고유명사 후보가 나오면 `search_web`(출처 직접 확인)이나 `search_agent`(출처를 단 요약)를 불러 공식 표기를 확인하고, 출처 URL을 판정 기록에 남깁니다.
- **원고 보호**
  - 이 프로젝트는 원고가 컴퓨터 밖으로 나가지 않는 것을 원칙으로 합니다(전사·번역은 로컬).
  - 그래서 라이너에는 **고유명사 낱말만** 보냅니다. 대사 문장 전체는 보내지 않습니다.
- **결과 재사용**
  - 확인한 표기는 작품별 용어집에 쌓아, 같은 낱말은 다시 검색하지 않습니다.

## 4. 기대 효과와 측정 계획

효과를 숫자로 약속하지 않고, 개발물 제출(11/25)까지 아래 항목을 실제로 재서 보고합니다.

| 지표 | 재는 법 |
|---|---|
| 인점·아웃점 정확도 | 사람이 확정한 납품 SRT(정답)와 비교해, 인점·아웃점이 1프레임(0.04초) 안에 든 비율과 자동 확정 비율 |
| 규정 위반 감소 | 같은 영상에서 범용 LLM 초안과 에이전트 결과의 위반 건수(글자 수·CPS) 비교 |
| 고유명사 표기 정확도 | 고유명사 목록을 사람이 정답 표기와 대조 — 라이너 연동 전과 후 |
| 사람 손이 가는 자막 수 | 최종본에서 "사람 확인" 카드로 남은 자막 비율 |
| 작업 시간 | 같은 구간을 손으로 할 때와 에이전트를 거친 뒤 감수만 할 때의 시간 비교 |

기대하는 변화:
1. **반복 검수에 쓰는 시간 감소**: 규정 위반 찾기와 고유명사 확인을 에이전트가 먼저 처리하고, 번역가는 뜻과 뉘앙스 감수에 집중합니다.
2. **SDH 자막 품질 균일화**: 효과음 표기([문이 쾅 닫힌다], [비장한 음악])와 읽기 속도 규정을 매번 같은 기준으로 검사해, 청각장애인 시청자가 받는 자막 품질의 편차를 줄입니다.
3. **40대 이상 실무자의 현장 노하우를 자산으로**: 코딩 비전공 실무자가 AI 코딩 도구와 라이너 API로 자기 분야의 문제를 직접 푸는 사례를 만듭니다.

## 5. [11/11 접수용] 온라인 신청서 제출 텍스트 요약

```text
[프로젝트명]
현업 영상번역가의 암묵지를 이식한 SDH 자막 자가교정(Judge & Refine) AI 에이전트

[해결하려는 실무 문제]
영상 자막과 청각장애인용 SDH 자막은 줄당 글자 수(예: 넷플릭스 한국어 16자·2줄), 읽기 속도(번역 12자/초·SDH 14자/초), 화면 전환을 넘지 않는 타임코드 같은 엄격한 규정을 지켜야 합니다. 범용 LLM은 이 규정을 모르고 문장을 늘여 쓰거나 고유명사 표기를 지어내, 번역가가 한 줄씩 다시 손봐야 합니다. 숙련 번역가의 머릿속에만 있던 압축·검수 노하우를 에이전트로 옮기려 합니다.

[에이전트 작동 방식]
먼저 현업 순서대로 타임코드를 잡습니다. 전사 없이 오디오의 말소리 경계를 찾고, 발주처 규정 여유(인점은 말소리 2~3프레임 앞, 아웃점은 말끝 6~9프레임 뒤, 겹치면 인점 우선, SDH는 화면 전환 앞뒤 0.5초)를 적용합니다. 오차 0.04초 미만으로 판정된 구간만 자동 확정해 잠그고, 나머지는 사람이 확인합니다. 그다음 잠긴 타임코드 안에서 자막을 만들고, 규칙 코드가 글자 수·읽기 속도·고유명사를 판정합니다. 고유명사는 라이너 서치 API·MCP로 공식 표기를 출처와 함께 확인하고(대사 원문은 보내지 않고 낱말만 검색), 위반한 자막만 LLM이 타임코드는 그대로 둔 채 뜻을 살려 압축합니다. 다시 판정해 통과할 때까지 최대 3회 되풀이하고, 남은 문제는 사람 확인으로 넘깁니다.

[기대 효과]
번역가가 규정 위반 찾기와 고유명사 확인에서 벗어나 감수에 집중하고, 청각장애인용 자막 품질을 같은 기준으로 고르게 맞춥니다. 효과는 인점·아웃점 정확도·위반 건수·표기 정확도·작업 시간으로 재서 개발물과 함께 보고합니다.
```
