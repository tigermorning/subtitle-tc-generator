## 1. 해결하려는 문제

영상 자막 작가로 데뷔를 준비하며 직접 겪은 문제입니다.

### 여럿이 나눠 쓰는 자막은 밋밋해진다
- 방송·OTT 자막은 마감이 빠듯해 일을 여러 사람이 나눠 맡습니다.
  - **타임코드(TC)**: 말소리를 화면 단위로 끊고 인점·아웃점을 찍음
  - **자막**: 그 화면 안에 들어갈 글(받아쓰기·번역)을 씀
  - **검수**: 발주처 규정 위반과 표기 오류를 잡음
  - **번역**도 한 작품을 여러 사람이 나눠 하는 경우가 많습니다.
- 그러다 보니 인물마다 개성을 살린 말투보다 누구나 맞추기 쉬운 무난한 말투를 택하게 되고, 자막은 밋밋해집니다.

### 한 사람이 끝까지 맡으려면
- 한 사람이 작품을 끝까지 맡으면 인물마다 말투를 살릴 수 있고, 이는 데뷔를 앞둔 작가가 기성 작가와 겨룰 수 있는 강점이 됩니다.
- 다만 그러려면 여럿이 나눠 하던 일을 혼자서 빠르게 해내야 합니다.

### 그 일의 상당 부분은 반복 확인이다
판단보다 반복 확인에 가까운 일들입니다.

1. **인점·아웃점을 프레임 단위로 맞추기** — 화면 전환에 걸리는지도 다시 확인
2. **발주처마다 다른 규정과 줄마다 대조하기**
   - 예: 넷플릭스 한국어는 **줄당 16자·최대 2줄**, 읽기 속도 **번역 자막 12자/초, SDH 14자/초**(저장소 `rules/learned/netflix/ko-*.yaml` 머리말). 줄당 14자로 조이는 발주처도 있습니다.
3. **고유명사 표기 점검** — 인명·브랜드·작품명
4. **띄어쓰기·맞춤법 점검**
5. **1차 번역** — 원문의 뜻을 옮기는 초벌

사람의 손이 꼭 필요하지 않은 이 일들을 덜어 내면, 작가는 실력이 드러나는 **윤문**에 집중해 인물에 꼭 맞는 말투로 작품을 옮길 수 있습니다.

## 2. 에이전트의 원칙과 구조

### 원칙: 대충하는 기계가 아니라, 전문가가 믿고 맡길 수 있는 자동화
이 에이전트는 대충 초안을 만들어 놓고 사람이 다시 손보게 하는 기계가 아니라, 전문가가 믿고 맡길 수 있도록 **완벽에 가까운 자동화**를 목표로 합니다.

| 기계에 맡기는 일 | 기계가 맡아도 되는 이유 |
|---|---|
| 띄어쓰기·맞춤법, 글자 수·읽기 속도 | 정해진 규칙으로 판정할 수 있는 일 — 지치지 않고 같은 기준을 지키는 기계가 사람보다 실수를 줄일 수 있는 영역 |
| 타임코드(인점·아웃점) | 말소리 경계를 찾아 발주처 규정에 맞추는 기술적인 작업 — 기계가 그 수준으로 해낸다면 사람이 프레임 단위로 붙잡고 있을 이유가 없음 |
| 1차 번역 | 원문의 뜻을 옮기는 초벌 — 기계가 빠르게 만들고, 사람은 그 위에 인물의 말맛을 입힘 |
| 고유명사 표기 | 공식 표기를 찾아 출처와 함께 확인하는 조사 작업 |

"완벽에 가까움"을 지키는 장치:
- **숫자로 판정할 수 있는 것은 규칙 코드**가 판정합니다. LLM이 "대충 맞다"고 넘기지 않습니다.
- **기준을 넘은 것만 확정**합니다. TC는 오차 1프레임(0.04초) 안으로 판정된 구간만 자동 확정합니다.
- **확신하지 못한 곳은 억지로 채우지 않고** 이유를 붙여 사람에게 넘깁니다.
- 사람에게 남는 일은 **윤문**(인물에 맞는 말투 다듬기)과, 에이전트가 넘긴 확인 카드뿐입니다.

### 구조
현업 작업 순서를 그대로 따릅니다. **TC를 먼저 잡아 확정하고 잠근 뒤**, 그 틀 안에서 자막 문장을 만들고 고칩니다.

- **A. TC 작업** — 전사 없이 소리만 보고 인점·아웃점을 잡아 확정·잠금
- **B. 자막 작업** — 잠긴 TC 안에서 전사·1차 번역·줄바꿈을 하고, **판정(Judge) → 교정(Refine)을 되풀이하는 자가교정 루프**로 다듬음

### A. TC 작업 — 인점·아웃점을 잡는 법

기성 작가가 파형을 보며 손으로 찍던 인·아웃점을, 소리 신호와 발주처 규정으로 계산합니다.

```
[영상/오디오]
       ↓
[A-1: 말소리 구간 검출]
  - 전사 없이 오디오만으로 말소리가 시작·끝나는 경계를 찾음 (Silero VAD)
  - 배경음악·효과음이 큰 장면은 대사 성분을 먼저 분리해 경계를 또렷하게 함
       ↓
[A-2: 발주처 규정 여유 적용 (규칙 코드)]
  - 인점: 말소리 시작보다 2~3프레임 앞
  - 아웃점: 말끝보다 6~9프레임 뒤
  - 앞 자막 아웃점과 다음 자막 인점이 겹치면 인점 우선
  - 최소·최대 표시 시간 지키기
  - 여유값은 코드에 박지 않고 발주처 규정 파일에서 읽음
       ↓
[A-3: 화면 전환 (SDH 작업만)]
  - 화면 전환을 검출해, 전환 앞뒤 0.5초 안에 걸친 인·아웃점을 전환 지점에 맞춤
  - 우선순위: 인점 > 화면 전환 > 아웃점
       ↓
[A-4: 자동 확정과 잠금]
  - 말소리 경계 + 규정 여유와의 오차가 0.04초 미만(1프레임 안팎)이라고 판정된 구간만 자동 확정
  - 확신이 낮은 구간은 "사람 확인" 카드로 넘김 (파형 위치·이유 표시)
  - 확정한 TC는 잠금 — 이후 단계는 TC를 움직이지 않음
```

### B. 자막 작업 — 자가교정 루프

```
[잠긴 TC + (있으면) 원어 대본]
       ↓ 전사(faster-whisper) → 대본 대조
       ↓ 1차 번역 (Liner Model API, 번역 작업만)
       ↓ 줄바꿈
[B-1: 판정 (규칙 코드, 결정론적)]
  - 차원 1: 글자 수 (줄당 상한·줄 수, 발주처 규정 파일 값)
  - 차원 2: 읽기 속도 (잠긴 TC의 표시 시간 대비 CPS 상한)
  - 차원 3: 띄어쓰기·맞춤법
  - 차원 4: 고유명사 후보 표시 (검증이 필요한 낱말만 골라냄)
       ↓
       ├─ [위반 0건] ──→ [윤문용 자막 출력 (SRT/VTT)]
       └─ [위반 있음]
              ↓
[B-2: 고유명사 확인 (Liner Search API·MCP)]
  - 차원 4가 고른 낱말만 검색해 공식 표기를 출처와 함께 확인
              ↓
[B-3: 교정]
  - 띄어쓰기·맞춤법·고유명사 표기: 자동으로 바로잡음
  - 글자 수·읽기 속도 초과: Liner Model API가 뜻을 살린 줄임안을 냄 (TC는 그대로)
              ↓
[B-1로 돌아가 다시 판정 — 최대 3회]
  - 3회 뒤에도 남은 위반은 억지로 고치지 않고 "사람 확인" 카드로 넘김
    (위반 규칙 ID·자막 번호·이유 표시)
```

TC가 잠겨 있으므로, 읽기 속도를 넘기면 **TC를 늘리지 않고 문장을 줄여서** 맞춥니다. 기성 작가가 하는 방식 그대로입니다.

출력은 "다 끝난 자막"이 아니라 **규정·표기·타이밍이 맞춰진, 윤문만 남은 자막**입니다. 작가는 이 위에서 인물마다 말투를 다듬습니다.

## 3. 라이너 API 접목 방안

- **Liner Model API — 1차 번역과 줄임안**
  - **1차 번역**: 원문의 뜻을 옮기는 초벌을 만듭니다. 대본이 있으면 대본과 대조한 문장을 넘깁니다.
  - **줄임안**: 글자 수·읽기 속도를 넘긴 자막을 뜻을 살려 줄입니다. 판정 결과(어느 규칙을 몇 자 넘겼는지)와 확인한 고유명사 표기를 함께 넘깁니다.
  - OpenAI·Anthropic SDK와 호환되므로, 기존 코드에서 주소와 키만 바꿔 연결합니다.
  - 판정은 규칙 코드가 하므로, 모델이 쓴 문장도 매번 다시 숫자로 검사받습니다.
- **Liner Search API·MCP — 고유명사 확인**
  - 에이전트 루프에 라이너 원격 MCP 서버를 도구로 등록합니다.
  - 고유명사 후보가 나오면 `search_web`(출처 직접 확인)이나 `search_agent`(출처를 단 요약)로 공식 표기를 확인하고, 출처 URL을 판정 기록에 남깁니다.
  - 확인한 표기는 작품별 용어집에 쌓아, 같은 낱말은 다시 검색하지 않습니다.
- **원고 보호 선택지**
  - 대회 시연은 공개 데이터로만 하므로 Liner Model API를 씁니다(아래 4절).
  - 실제 의뢰 원고를 다룰 때는 번역·줄임 모델을 로컬 모델로 바꿀 수 있게 설정으로 둡니다. 이때도 라이너 검색에는 대사 문장이 아니라 고유명사 낱말만 보냅니다.

## 4. 시연 데이터와 측정 계획

### 시연 데이터 (참가 규정 제5조 준수)
- 회사 내부 자료·의뢰받은 원고·납품 자막은 쓰지 않습니다.
- **저작권 문제가 없는 공개 영상**을 쓰고, 그 영상의 정답 자막은 **신청자가 직접 만들어** 함께 공개합니다.
- 규정값은 공개된 발주처 스타일 가이드에서 가져옵니다.

### 측정 계획
"완벽에 가까운 자동화"는 목표이므로, 결과물 제출(11/25)까지 아래 항목을 재서 숫자로 보고합니다.

| 지표 | 재는 법 |
|---|---|
| 인점·아웃점 정확도 | 직접 만든 정답 자막과 비교해, 인점·아웃점이 1프레임(0.04초) 안에 든 비율과 자동 확정 비율 |
| 규정 위반 | 같은 영상에서 범용 LLM 초안과 에이전트 결과의 위반 건수(글자 수·CPS) 비교 |
| 띄어쓰기·맞춤법 오류 | 에이전트 결과에 남은 오류 건수 — 사람이 손으로 했을 때와 비교 |
| 고유명사 표기 정확도 | 고유명사 목록을 정답 표기와 대조 — 라이너 연동 전과 후 |
| 사람 손이 가는 자막 수 | 최종본에서 "사람 확인" 카드로 남은 자막 비율 |
| 작업 시간 | 같은 구간을 신청자가 처음부터 손으로 할 때와, 에이전트를 거친 뒤 윤문만 할 때의 시간 비교 |

## 5. 기대 효과와 확장성

1. **한 사람이 작품을 끝까지**: TC·자막·검수·1차 번역으로 나뉘던 일을 에이전트가 먼저 처리해, 작가 한 사람이 작품 전체를 맡을 수 있습니다.
2. **인물이 살아 있는 자막**: 여럿이 나눠 쓰느라 무난한 말투로 맞추던 자막 대신, 한 작가가 인물마다 어울리는 말투로 윤문할 시간이 생깁니다.
3. **실수 없는 기본기**: 띄어쓰기·맞춤법·규정·표기를 매번 같은 기준으로 맞춰, 사람이 지쳐서 놓치는 실수를 줄입니다. SDH 효과음 표기([문이 쾅 닫힌다], [비장한 음악])와 읽기 속도도 같은 기준으로 검사해, 청각장애인 시청자가 받는 자막 품질의 편차를 줄입니다.
4. **다른 발주처·언어로 확장**: 규정은 코드가 아니라 발주처별 규정 파일에 있으므로, 파일을 더하면 다른 발주처와 다른 언어 자막에도 같은 에이전트를 쓸 수 있습니다.

신청 폼의 "간단한 기획 내용" 두 칸에 넣은 글의 최종안입니다. 실제 제출본은 신청자가 폼에서 직접 다듬었을 수 있습니다.

[풀고 싶은 문제]
영상 자막 작가로 데뷔를 준비하며 직접 겪은 문제입니다. 방송·OTT 자막은 마감이 빠듯해 타임코드(TC), 자막, 검수를 각기 다른 사람이 맡고, 번역도 한 작품을 여러 사람이 나눠 하는 경우가 많습니다. 그러다 보니 인물마다 개성을 살린 말투보다 누구나 맞추기 쉬운 무난한 말투를 택하게 되고, 자막은 밋밋해집니다. 한 사람이 작품을 끝까지 맡으면 인물마다 말투를 살릴 수 있고, 이는 데뷔를 앞둔 작가가 기성 작가와 겨룰 수 있는 강점이 됩니다. 다만 그러려면 여럿이 나눠 하던 일을 혼자서 빠르게 해내야 합니다. 그런데 그 과정의 상당 부분은 판단보다 반복 확인에 가깝습니다. 인점·아웃점을 프레임 단위로 맞추는 일, 발주처마다 다른 글자 수·읽기 속도 규정(예: 넷플릭스 한국어 줄당 16자, SDH 초당 14자)과 줄마다 대조하는 일, 고유명사 표기와 띄어쓰기·맞춤법을 하나하나 점검하는 일이 그렇습니다. 사람의 손이 꼭 필요하지 않은 이 일들을 덜어 내면, 작가는 실력이 드러나는 윤문에 집중하며 인물에 꼭 맞는 말투로 작품을 옮길 수 있습니다.

[만들 에이전트가 해 줄 일]
이 에이전트는 대충 초안을 만들어 놓고 사람이 다시 손보게 하는 기계가 아니라, 전문가가 믿고 맡길 수 있도록 완벽에 가까운 자동화를 목표로 합니다. 띄어쓰기·맞춤법, 글자 수·읽기 속도처럼 정해진 규칙으로 판정할 수 있는 일은, 지치지 않고 같은 기준을 지키는 기계가 사람보다 실수를 줄일 수 있는 영역입니다. 타임코드 역시 말소리가 시작하고 끝나는 지점을 찾아 발주처 규정에 맞추는 기술적인 작업이라, 기계가 그 수준으로 해낸다면 사람이 프레임 단위로 붙잡고 있을 이유가 없습니다. 1차 번역도 마찬가지입니다. 원문의 뜻을 옮기는 초벌은 기계가 빠르게 만들 수 있으니, 사람은 그 위에서 인물의 말맛을 입히는 데 힘을 쓰면 됩니다. 그래서 영상을 올리면 에이전트가 인점·아웃점을 잡되 오차가 1프레임 안으로 판정된 곳만 확정하고, 라이너 모델 API로 1차 번역을 만듭니다. 이어서 자막을 줄마다 검사해 띄어쓰기·맞춤법을 바로잡고, 고유명사는 라이너 서치 API로 공식 표기를 출처와 함께 확인하며, 규정을 넘긴 줄은 라이너 모델 API가 뜻을 살린 줄임안을 내놓습니다. 기준에 못 미치거나 확신하지 못한 곳은 억지로 채우지 않고 이유를 붙여 사람에게 넘기므로, 작가는 결과를 믿고 인물에 맞는 말투를 다듬는 윤문에만 시간을 쓰면 됩니다.
