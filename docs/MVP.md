# MVP — 지금 실제로 되는 것

[`PRD.md`](PRD.md)의 목표에 대해 **지금 이 저장소가 실제로 하는 일**만 적는다.
계획이나 바람이 아니라 동작 확인된 것 — 근거는 README·git 커밋·`tests/run_tests.py`
통과 여부다. 새로 지어내지 않는다.

## 되는 것

### 규정 검사 (CLI, `python -m checker`)

- 넷플릭스(한국어·영어, SDH·번역, `official: true`, Korean TTSG 2025-07-07 개정
  기준), 디즈니+·쿠팡플레이(한국어, SDH·번역, `official: false` — 공식 문건
  미확보라 작업자 실무 자료 기준)
- 위반마다 조항 번호 인용, `[자동]`/`[확인]` 구분, 미구현 검사는 숨기지 않고
  `미구현 검사`로 별도 표기
- `--fix`(자동 교정, 원본 불변·새 파일로 출력), `--fix-timing`, `--korean`(한국어
  교정기 레인 연동), `--terms`(용어 조사), `--characters`(캐릭터 분석 문서),
  `--backtranslate`(역번역 검증)
- **결정표**(2026-09-08, `checker/decisions.py`): 발주처·종류·언어를 사람이 고른
  것인지 기계가 기본값으로 채운 것인지 구분해 낸다. 안 고르면 예전과 같은 값
  (`netflix`/`translation`)으로 채우되 경고하고, 리포트에 `decisions`로 남긴다.
  장르 미지정과 `--translate`인데 캐스트 시트가 없는 것(인물 관계를 모른 채
  존댓말로 통일됨)도 같이 낸다. `--generate`·`--dry-run`은 실행 앞머리에 표로
  찍는다 — `preflight`(환경 점검)와 다른 층이다

### 자막 초벌 생성 (`--generate`)

- 영상 → ffmpeg 내장 whisper 전사 → (스크립트 있으면 대조) → 의미 단위 재분할
  → Silero VAD(없으면 음량) 기반 스포팅 제안 → 규정 자동 교정 → 검사까지 한 번에
- 화자명은 스크립트 없이는 못 넣는다(whisper가 화자 분리를 못 함 — 정직하게 표시)
- 번역은 `--translate`로 로컬 Ollama 다차 검수(1차 정확도 → 2차 용어·맥락 →
  3차 윤문·글자 수), 드리프트 가드·역번역 검증 포함

### 정답 대조 (`--against`)

- 우리 결과와 정답 자막을 구조적으로 대조(짝지음/빠뜨림/군더더기, 인점·아웃점
  편향의 가운데값·흩어짐·최악)
- **2026-08-26 첫 실전 사용**으로 `checker/timing.py`의 실제 구조적 버그(스포팅이
  근처 말소리 구간 전체 끝까지 과도하게 늘어나는 문제)를 발견·수정함 —
  `.claude/skills/정답지-대조-진단/`이 이 절차를 코드화한다
- **2026-08-30**: 정답지 있는 영상은 아래 코퍼스 학습부터 예외 없이 먼저 하고,
  이 대조(비용 큰 whisper 필요)는 그 뒤 필요할 때만 한다(CLAUDE.md 규칙 13).
  같은 발주처+장르 연속 3편에서 새 구조 버그가 없으면 "성숙"으로 보고 그다음부턴
  코퍼스 학습만으로 충분할 수 있다 — `rules/private/corpus/corpus_status.yaml`의 `genre_maturity`가
  이 판단을 기록한다(사람 확인 전엔 자동 전환 없음)

### 코퍼스 학습 (`rules/learned/`)

- `tools/corpus_build.py`로 시판·방영 영상의 정답 자막 트랙에서 통계(글자 수·CPS·
  듀레이션·간격 분포)를 추출
- 2026-08-26 기준 10개 발주처 버킷(netflix·disney·coupang·amazon·appletv·hbo·
  viki·viu·bluray·unknown) 아래 학습값 존재 — `platform: unknown`은 발주처를
  특정 못 한 자료(예: 다발매 PVOD 영화)를 위한 임시 버킷
- **공식 규정 파일(`rules/<platform>/`)을 절대 건드리지 않는다** — 학습값은
  `rules/learned/`에만 쌓이고, 규정으로 승격하려면 사람 확인을 거친다(CLAUDE.md
  규칙 11)
- `.claude/skills/정답지-학습/`이 이 전체 절차(무결성 확인→추출→기록→백업→정리)를
  코드화한다
- **`--generate`가 실제로 이 값을 쓴다(T14, 2026-09-01).** `resplit.py`가
  `chars_per_cue` 중앙값을 읽어 **자를 자리를 그 글자 수 쪽으로 당긴다**.
  규정 상한(`per_line × max_lines`)은 안 건드린다 — 여러 합법 후보 중 어느
  것을 고를지만 바꾼다(규칙 11: 규정이 정한 값은 겨루지 않는다). 엄격 일치만
  쓴다 — platform·language·kind가 정확히 같을 때만 본다(폴백 금지, 사용자
  확인 2026-09-01)
- **2026-09-08 백필**: 그 경로가 오랫동안 `disney/ko-sdh` 하나에서만 돌았다
  (나머지 파일은 `chars_per_cue`가 생기기 전에 뽑혀서 그 칸이 비어 있었다).
  정답지 `.srt`가 남아 있는 조합을 같은 자료로 다시 재서 채웠다 —
  `netflix/ko-sdh`(9.5)·`netflix/ko-translation`(8.5)·
  `netflix/en-translation`(28.0)·`disney/ko-translation`(17.0)·
  `coupang/ko-sdh`(11.0). 기존 항목을 함께 다시 재서 적힌 값과 전부
  일치함을 확인했다(`tools/learned_chars_per_cue.py`)
- **아직 안 쓰는 곳**: `--check`의 판정, 스포팅 듀레이션 선택. 프로파일이 없는
  발주처(amazon·bluray 등)의 학습값도 소비되지 않는다 — 그 조합은 애초에
  `--generate`가 못 도는 조합이다

### 화면 캡션 인식 (`--ocr-scan`/`--ocr`/`--ocr-hardsub`, 2026-08-30~31)

- EasyOCR을 격리 venv(`.venv-ocr/`)에서 서브프로세스로 돌려, 화면에 타 있는
  글자(그래픽 자막·하드섭)를 읽는다. `--ocr-scan`은 목록만 내는 보고용(규칙4
  — 화면 글자 검출은 추정), `--ocr`은 `--generate`에서 실제 최종 자막에
  얹는다(`--fn-marker` 필요), `--ocr-hardsub`은 임베디드 자막 트랙이 아예
  없는 하드섭 영상을 카드 단위 초안 srt로 뽑는다(정답지 아님 — 사람이 영상과
  대조해 고친 뒤에만 학습 자료가 된다)
- `full_scan`(seek 없이 연속 디코딩) 기본, 편집 유사도 기반 프레임 병합,
  겹침 방지까지 실측 검증됨(2026-08-30~31, 예능A 19회)
- **2026-08-31, "제대로 구축됐는지" 검증 요청으로 실제 서브프로세스를 처음
  돌려 구멍 셋을 찾아 고쳤다**: 첫 실행이 Windows 콘솔 인코딩(cp949)으로
  100% 크래시하던 것, 프레임 하나가 손상되면 전체 스캔이 죽던 것, `--ocr-
  hardsub`(71분 영상 기준 7~8시간짜리 스캔)이 끊기면 처음부터 다시 돌아야
  했던 것 — 마지막은 프레임마다 결과를 디스크에 남기고 재시작하면 이어
  받는 체크포인트로 해결. 셋 다 합성 영상으로 진짜 재현·재검증함
  (`docs/HANDOFF.md` 참고)

### 비대사 소리 짐작 (`--sfx-scan`/`--sfx`, 2026-08-31)

- AudioSet 오디오 분류 모델(`MIT/ast-finetuned-audioset-10-10-0.4593`, 시스템
  파이썬에서 바로 돎 — 격리 venv 불필요)로 **VAD가 이미 "대사 없음"으로 확정한
  구간**마다 무슨 소리 계열인지 짐작한다. whisper는 말소리만 받아 적어 정답
  SDH에 있는 순수 효과음 자막(`[groans]` 등)을 처음부터 못 만든다는 것을
  실측 확인(영화B·영화A·드라마B 정답 대조)한 데
  대한 답
- `--sfx-scan`은 보고용(1단계), `--sfx`는 `--generate`에서 실제 최종 자막에
  얹는다(**-l ko -k sdh 전용** — 후보 문구가 한국어뿐). 얹은 자리는 신뢰도와
  무관하게 예외 없이 "확인 필요"로 표시된다(OCR과 다른 점 — 오디오 분류는
  소리 계열만 맞혀도 정확한 한국어 표현은 항상 사람이 다듬어야 하는 초벌)
- 분위기(따뜻한/슬픈 등)·구체 동작(신발 벗는 소리 등)은 오디오만으로 못
  정한다 — `rules/lexicon/ko-sdh-effects.yaml`의 수식어 없는 일반형 후보만 낸다

## 알려진 미해결

- **whisper가 노래·박수·군중 반응을 대사로 오인해 전사하는 문제는 근본 해결이
  아직 없다** (의도적 미착수가 아니라 미해결이라 여기로 옮김 — 원래 "범위 밖"에
  있었다). 2026-08-26, 세 작품(예능A·영화D·영화F, 한국어
  예능·영어 실사영화·영어 애니메이션)에서 공통 확인됨 — 스포팅이 길게 늘어짐.
  `checker/timing.py`의 스포팅 확장 상한(`max_shift_ms`)이 가장 심한 과확장만
  막을 뿐, 원인(오디오만으로 "이게 대사인지" whisper 스스로 못 가림)은 남아
  있다. `BACKLOG.md`에 다음 작업으로 남김. **혼동하지 말 것**: 이것은 whisper가
  "말소리 구간"이라고 잘못 판단하는 문제이고, VAD가 이미 "대사 없음"으로
  **맞게** 확정한 구간에 무슨 소리인지 짐작하는 것은 별개로 위 `--sfx-scan`이
  한다(2026-08-31) — 둘 다 오디오 이해와 관련되지만 서로 다른 문제다
- **UI 멈춤(AppHangB1)** — Windows 이벤트 로그에 남는 실사용 멈춤. 2026-08-14
  기준 "고쳤다고 보지만 확인 못 했다"(`BACKLOG.md` §0-A) — 이후 재확인 기록 없음
- 문서화 형식 임계값(다큐 합니다체 비율 등, `T4`)은 완성본 자막 표본이 더 쌓일
  때까지 보류 — 자세한 것은 `BACKLOG.md`
