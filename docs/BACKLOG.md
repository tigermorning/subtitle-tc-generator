## 0-A. 지금 막혀 있는 것 — **여기부터**

### 실사용 멈춤 (AppHangB1) — 고쳤다고 보지만 확인 못 했다

**증상.** 영상에서 자막을 만들면 생성은 끝까지 가는데(자막 208개까지 나온다) **그 뒤
UI가 멈춘다.** Windows 이벤트 로그가 `AppHangB1`을 남긴다 — 크래시가 아니라 UI 실이
이벤트를 못 돌린 것이고, 파이썬 예외 기록은 없다. 두 번 재현했다(22:26, 22:36).

**밝혀낸 것.**

- 생성 자체는 문제가 없다. `.work/01-generate.srt`에 자막 208개가 남는다.
- Qt 쪽은 빠르다. 같은 규모(자막 210개·지적 118건)를 mpv 없이 재현해 재 봤다:
  `model.replace` 8.9ms · 파형 10.0ms · 지적표 9.0ms · `_refresh_stages` 1.0ms.
- 남는 것은 **UI 실에서 도는 동기 mpv 왕복**이다. `python-mpv`의 `command()`는 답을
  기다린다.
- ONNX(VAD)는 이미 단일 스레드다(`inter_op=1, intra_op=1`) — CPU 포화 가설은 죽었다.

**한 조치 둘.**

1. `fit_subtitle_scale()`을 100ms 시계에서 빼고 `resizeEvent`로 옮겼다. mpv 왕복을
   초당 20번 UI 실에서 기다리던 것이다(그 함수 독스트링이 "창 크기가 바뀔 때마다"라고
   적고 있었다). 멈춰 있으면 시계를 500ms로 늦춘다. → 커밋 `25ce0d3`
2. `set_subtitles`/`reload_subtitles`를 `command_async`로 바꿨다. 생성 직후 자막 208개를
   mpv에 **처음 얹는** 자리가 `sub-add`이고 그것이 가장 유력하다. → **아직 커밋 전이면
   `app/player.py`를 확인**

**다음 사람이 할 일.**

- exe를 재빌드하고 같은 영상으로 다시 돌린다. **그것이 유일한 시험이다.**
- 여전히 멈추면 다음 후보는 `_sync_position`의 `position_ms`(속성 읽기, 100/500ms마다)와
  `player.seek`(파형 클릭). 같은 방식으로 비동기화하거나, 재생기 조작을 전부 한 곳으로
  모아 UI 실에서 mpv를 만지지 않게 한다.
- **막힌 지점을 증명하지는 못했다.** 스택을 뜨려면 procdump 같은 도구가 필요하다.

**재빌드가 막힐 수 있다.** 멈춘 `자막생성기.exe`가 `dist` 파일을 잠근다. 작업 관리자로

## 2. 끝난 것 (되돌리지 말 것)

- **`pipeline.py`로 오케스트레이션 일원화.** 네 어댑터(CLI 검사·CLI 생성·GUI·SE
  플러그인)가 모두 `correct_and_check`를 부른다. 선언한 `STAGES`마다 `stage_` 함수가
  있는지 시험이 잰다.
- **검사는 맨 끝.** 원본만 검사하면 교정이 만든 새 위반을 못 본다. 실측 사례가
  시험에 박혀 있다(`3천 불` → `3천 달러`가 글자 수 한계를 넘긴다).
- **`formality.py`** — 말투를 센다. 확정(합니다체·해요체)만 세고 반말은 유보.
- **`characters.py`** — 캐릭터 분석 문서. 자막이 증명하는 것만 채우고 나머지는
  '확인 필요'로 둔다.
- **모델 기본값 한 곳**(`translate.DEFAULT_MODEL`).
- **회차 상한 없음**(`stage_revise(rounds=n)`).
- **`genre.py` + `rules/genre/`** — 장르를 플랫폼 프로파일 **위에 얹는다**. 프롬프트가
  아니라 프로파일 층이어야 검사기가 본다(자료 590행이 장르로 TC 길이를 가른다).
  다큐·드라마·예능 셋. `--genre`로 켠다.
- **`~씨` 검사(G01)** — 다큐·리얼리티에서만. 화자명·낱말(`씨앗`)·지시어(`그 씨`)는
  거른다. 극존칭(G02)은 자료에 정의가 없어 **미구현으로 밝힌다**(규칙 9).
- **권장 표시 시간·합니다체 비율을 리포트에 숫자로** 낸다. 위반 목록에 섞지 않는다 —
  권장은 규정이 아니다(규칙 4·5).
- **`AGENTS.md`** — opencode·Codex는 `AGENTS.md`를 자동으로 읽고 `CLAUDE.md`는 읽지
  않는다. 규칙이 도구에 따라 빠지지 않게 입구를 만들었다.
- **생성 결과를 `.work/`에 남긴다.** 화면에 넘기기 **전에** 남기므로 화면 쪽이 멈춰도
  결과는 살아 있다. 실사용에서 210개를 그렇게 잃었다.
- **UI 실에서 mpv 왕복을 덜어냈다.** `fit_subtitle_scale`을 100ms 시계에서 빼고
  `resizeEvent`로 옮겼다(초당 20번 → 창 크기 바뀔 때만). 멈춰 있으면 시계를 500ms로 늦춘다.
- **단계 메뉴(`단계(&S)`).** 단추만 있으면 키보드로 못 가고 무엇이 있는지 훑을 수도
  없다. `stage_actions`를 만들어 두고 아무 데도 붙이지 않았던 것을 붙였다.
- **단계를 줄기별로 갈라 그린다.** `Stage.track`으로 소재·번역·한국어·조사 네 줄.
  `[① 1차 번역] [② 번역 감수 (회차)] [③ 자막 윤문·QA]`가 눈에 보이고, 줄기마다 직전
  결과 요약이 붙는다. **회차 선택이 화면에 있다.**
- **`stage_polish`·`stage_characters`.** ③은 윤문 -> 한국어 교정 -> 규정 검사를
  **파이프라인이** 잇는다 — 어댑터가 순서를 가지면 CLI와 갈라진다.
- **`work.py` + `.work/` 폴더.** 단계마다 남긴다 — CLI와 GUI 둘 다. 회차마다 따로
  남기므로 회차 사이를 견줄 수 있다. 타임코드는 첫 단계에서 굳고 이후 옮기면 기록에
  경고로 남는다. **남기기가 실패해도 본 작업은 멈추지 않는다.**
- **누적 표류 가드.** `revise(baseline=...)`가 **1차 대비**로도 재므로, 회차마다
  1.4배씩 늘어 원문 대비 2배가 되는 일이 막힌다(실측 2.70배 -> 1.40배).
- **수렴 조건과 멈춘 이유.** `--max-passes`/`--settle-at`. **상한에 걸린 것은 아직 덜
  됐다는 뜻**이라 다 끝난 것과 문구를 갈라 적는다.
- **`backtranslate.py` + `stage_backtranslate` + `--backtranslate`.** 번역을 원어로
  되돌려 원문과 견준다. **임계값을 두지 않는다** — 점수 낮은 순 상위 N개를 낸다
  (판정이 아니라 순위). 줄임말을 펴서 `don't`/`do not`이 어긋나 보이지 않게 한다.
- **`mistranslation.py` 층 1 검증.** 1차 직후 원문↔번역 대조. **넷 중 둘은 확정이
  아니다**(부정·숫자는 추정) — 그래서 전부 플래그로만 내고 규정 위반에 섞지 않는다.
- **프롬프트 세 단계 재배치.** 1차=오역+구조만, 2차=맥락·용어·말투, 3차=문체·간결·부호.
  **규칙이 두 단계에 겹치면 시험이 잡는다.** `DOCUMENTARY_RULES`(죽은 코드)를 지우고
  장르 규칙을 프로파일에서 읽는다(`revise.genre_hint`).
- **캐릭터 시트가 감수 프롬프트에 물린다**(`revise.cast_hint`). 정하고, 쓰고, 검사하는
  것이 한 자료다 — 같은 시트가 T17도 돌린다.
- **T17 `formality_inconsistent` 구현.** 캐릭터 시트의 `말투 지정` 칸과 견준다
  (`--cast`). 시트가 없으면 **`skipped_checks`로 "돌지 못했다"를 밝힌다** — 구현이
  끝나면 미구현 목록에서 빠지므로, 밝히지 않으면 "검사했고 통과"로 읽힌다.
- **`characters.read_tsv()`** — 시트를 되읽는다. **칸 순서가 아니라 머리글로 찾는다**
  (사람이 엑셀에서 칸을 옮긴다). `확인 필요`·`정해 주세요`는 빈 값으로 읽는다.
- **`webchars.py` + `characters.research()` + `--characters`** — 캐릭터 분석 문서에
  성별·나이·직업·경력·성격을 채운다(항목 이름은 작업자 자료가 정했다). 나가는 것은
  **작품 제목과 인물 이름뿐**이고 무엇을 보냈는지 기록한다. 사진은 주소와 라이선스만
  가져오고 동봉 판단은 작업자가 한다.

## 3. 남은 작업 — 이 순서로

**T1~T3, T5~T11이 전부 끝났다.** 남은 것은 T4의 절반(임계값 실측)뿐이고, 그것은 자료를
기다리는 일이다. 그래서 **다음 할 일은 §0-A(멈춤 확인)와 §4(결정 대기)에 있다.**

순서에 이유가 있다. 뒤 항목이 앞 항목을 전제로 한다.

### ~~T1. 캐릭터 시트 외부 조사~~ 〔끝남〕

`characters.py`의 `traits`·`photo`·`origin`을 채우는 조사 기능.

- **사용자가 "조회까지 다 만든다"로 결정했다.** 내가 제기한 우려(미공개작 제목
  조회가 작업 사실을 노출, 사진 저작권)를 듣고 재확인한 결정이다.
- **지켜야 할 것**(규칙 6, 이건 사용자가 뒤집지 않았다):
  - 나가는 것은 **작품 제목뿐**. 대사·대본은 어떤 경우에도 나가지 않는다.
  - **무엇을 보냈는지 기록에 남긴다.**
  - 사진은 로컬에 두고 **출처·라이선스를 함께 적는다**. 납품 문서 동봉 여부는
    작업자가 판단한다.
- 참고: `terms.py`의 `research(..., web=True)`가 이미 같은 성격의 외부 조회를
  한다. 그 무늬를 따른다.

**짓다가 잡은 것 둘:**

1. **이름이 정확히 같은 문서를 먼저 고른다.** 검색 순위에 맡기면 `Walter White`를
   찾았는데 `Walter White Jr.`가 1위로 왔다(실측). 아들·아버지처럼 이름이 겹치는
   인물은 작품마다 있고, 잘못 집으면 성격과 말투를 통째로 틀린 사람에게 붙인다.
2. **`{{...}}`를 통째로 지우면 안 된다.** 목록 틀에 싸인 값이 사라져
   `affiliation = {{Plainlist|...}}`가 빈칸이 됐다 — 경력 정보를 통째로 버렸다.
   규칙: 맨 인수는 내용, `키=값` 인수는 메타정보.

**남은 것:** 위키를 사람이 지정해야 한다(`--wiki`). 슬러그를 짐작하지 않기로 한
결정이다 — 엉뚱한 위키를 읽으면 엉뚱한 인물 정보가 나오고, 그건 없는 것보다 나쁘다.

### ~~T2. T17 `formality_inconsistent` 구현~~ 〔끝남〕

프로파일에 규칙으로 선언돼 있고 **미구현**이다(`netflix/ko-translation.yaml` T17,
"같은 관계에서 존댓말·반말이 섞였습니다").

**T1이 먼저인 이유:** 같은 화자가 존댓말과 반말을 섞는 것은 **상대가 다르면
정상**이다. 자막에 상대는 표시되지 않으므로, 관계를 모르는 채 지적하면 오답이 된다.
캐릭터 시트가 관계를 담은 뒤에야 T17이 성립한다.

**어떻게 풀었나.** 반말 판별을 새로 만들지 않았다. 사람이 시트에 "이 인물은 이렇게
말한다"를 적어 주고(`말투 지정`), **확정된 말투만 견준다.**

    정한 것 합니다체 · 이 줄 해요체   -> 어긋남 (둘 다 확정)
    정한 것 반말     · 이 줄 존댓말   -> 어긋남 (존댓말이 확정이므로 한 방향으로 잰다)
    정한 것 무엇이든 · 이 줄 유보     -> 넘긴다
    정해 주지 않은 인물               -> 건드리지 않는다

반말 확정은 여전히 못 한다(`해야` vs `뭐야`). 그래도 위 세 줄로 실제 어긋남은 잡힌다.

프로파일 문구도 실제로 재는 것과 맞췄다("같은 관계에서…" -> "캐릭터 시트에 정한
말투를 벗어났습니다").

### ~~T3. 장르 프로파일 셋~~ 〔끝남〕

`extends` 상속으로 얹는다. **프롬프트가 아니라 프로파일 층**이어야 한다 — 자료
590행이 장르로 **타임코드 길이**를 가르므로 검사기가 봐야 한다.

```
다큐(정통/리얼)  ~씨 금지, 극존칭 금지, TC 3~5초, 합니다체 위주
드라마           ~씨 가능, 극존칭 가능, TC 2~3초        ← 멜로가 여기 들어간다
예능/리얼다큐    TC 2초 이하
```

근거: `rules/sources/작업자-자료/작업 기본 원칙.txt` 146·312·590·658·659·889행.

**만들지 않는 것:**
- **멜로 프로파일** — 일반 대화체 = 드라마 기본값. 빈 프로파일을 늘리지 않는다.
- **느와르 프로파일** — 욕설은 이미 플랫폼 규정이다
  (`censorship.allowed: false` = 검열 금지 = 동등 강도 허용). 장르가 아니라
  **캐릭터**가 정한다 → T1으로 넘긴다.

**`DOCUMENTARY_RULES`(translate.py)는 죽은 코드다.** 정의만 있고 참조가 0건.
장르를 프로파일 층으로 옮기면서 지우거나 프로파일에서 읽게 바꾼다.

### T4. 다큐 합니다체 비율 — 〔절반 끝남: 숫자는 나온다, 임계값은 대기〕

문서·화자 단위로 비율만 낸다. `formality.summary()`가 이미 계산한다.

**줄마다 `요`를 잡으면 안 된다.** 사용자 확인: "다큐는 합니다체 위주이지만
**자연스러움을 위해 가끔씩 요를 사용하는 것은 허용된다**." 허용되는 것을 위반으로
부르면 오답이다.

**임계값을 지어내지 않는다.** "가끔"이 몇 퍼센트인지는 사용자의 **완성본 다큐
자막으로 재야** 안다. 재기 전까지는 숫자만 내고 판정하지 않는다. 근거 없는 임계값은
오답 공장이다(제42항에서 이미 겪은 무늬).

낼 자리: 위반 목록이 아니라 리포트의 별도 칸(`position_suggestions`와 같은 성격 —
추정은 지적하지 않고 따로 낸다, 규칙 4).

### ~~T5. 1차 번역 프롬프트 재배치~~ 〔끝남〕

`translate.SYSTEM`이 1차에 너무 많이 시킨다. 사용자 요구는 "1차는 정확도와
타임코드만".

| 지금 1차에 있는 것 | 가야 할 곳 |
|---|---|
| 마침표 금지, 문장부호 최소화 | ③ 윤문 |
| 인칭대명사 금지 | ③ |
| `수/있/것`·보조용언·`-시-` 덜기 | ③ |
| "불필요한 말은 과감히 뺀다" | ③ |
| 인물 관계 말투 | ② 감수 |
| 한국 문화 과하게 옮기지 않기 | ② |
| 오역 금지 | **① (이것만)** |

`SECOND_PASS`(revise.py)에도 같은 문체 규칙이 중복돼 있다. 규칙은 한 단계에만 둔다.

**주의(그대로 유효):** 1차 결과가 전보다 투박하다. 그게 의도지만 ③까지 안 돌리면
예전보다 나쁘게 보인다. `prefs.translate_passes`는 이미 3이고 GUI 체크박스도 3을
넘긴다. **실제 영상으로 돌려 확인한 적은 없다** — 다음 실사용에서 봐야 한다.

**짓다가 걸린 것:** 2차 프롬프트가 "말투는 1차를 따릅니다"라고 하고 있었다. 1차가
말투를 정하지 않게 되면 **아무도 정하지 않는 상태**가 된다. 그래서 말투를 정하는 것을
2차의 일로 명시했다(1차는 존댓말로 통일만 한다).

### ~~T6. 오역 검증 (층 1)~~ 〔끝남 — 다만 여기 적었던 판단이 틀렸다〕

**정정.** 이 넷을 "확정이므로 자동 지적한다"고 적어 두었는데 **둘은 확정이 아니다.**
짓다가 드러났다.

| 검사 | 실제 |
|---|---|
| 화자 표시 | **확정** — 개수가 다르면 구조가 깨졌다 |
| 용어 | **확정** — 통일표가 정답을 정해 준다 |
| 부정 | **추정** — `I don't know` -> `몰라요`. 부정 표시 없이 부정한다 |
| 숫자 | **추정** — `in 5 minutes` -> `곧`. 자막은 숫자를 버리기도 한다 |

그래서 전부 **플래그로만** 낸다(`mistranslation_flags`). 규정 위반 목록에 섞으면
위반 건수가 거짓이 된다.

**한 음절 한자 수사 함정.** `일 이 사 오 구 십 만`을 수사 목록에 넣었더니 `잠깐만요`가
'숫자 있음'으로 판정되어 **검사가 사실상 돌지 않았다.** 한자 수사는 두 음절 이상이거나
단위가 뒤에 붙을 때만 수사로 본다.

**어느 단계에서 재는지가 중요하다.** 1차 직후에만 뜻이 있다 — 1차는 압축하지 않기로
했으므로 이때 빠진 숫자·부정은 옮기지 않은 것일 가능성이 높다. 3차를 지난 자막에
같은 검사를 걸면 정상적인 압축을 오역으로 부른다.

### ~~T7. 역번역 검증~~ 〔끝남 — 여기 적었던 설계에 순환이 있었다〕

**역번역이 답인 이유는 읽기 편해서가 아니다 — 비교가 같은 언어끼리 되기 때문이다.**
영·한을 직접 견주려면 다국어 임베딩이 필요하고(torch ~2GB, exe가 불어난다) 점수만
나와서 무엇이 틀렸는지 못 본다. 역번역을 거치면 의존성 없이 낱말 겹침으로 재고,
사람에게 보일 근거가 그 자체로 남는다.

**정정.** "층1을 통과했지만 낱말 겹침이 낮은 자막만 역번역한다"고 적어 두었는데
**그건 순환이다** — 겹침은 역번역을 해야 계산된다. 역번역 전에는 어느 자막이 의심스러운지
알 방법이 없다. 그래서 **전수로 돌리고, 점수가 나온 뒤에 고른다.**

```
#42  원문    I never said I'd go alone
     한국어  혼자 가겠다고 했어요
     역번역  I said I would go alone        <- never가 사라졌다  (75%)
```

**임계값을 두지 않았다.** 자르는 것은 점수가 아니라 개수다(`--backtranslate-worst`,
기본 20) — 몇 점 이하가 오역인지는 실제 작업물로 재야 알고, 재기 전에 박으면 오답
공장이 된다. 다큐 합니다체 비율에서 한 판단과 같다.

**줄임말을 펴야 했다.** 안 펴면 원문 `don't`와 역번역 `do not`이 어긋난 것으로 보인다 —
**가장 중요한 신호인 부정이 바로 그 무늬**라 그냥 두면 못 쓴다. `n't`를 일반 규칙으로
먼저 걸면 `can't`가 `ca not`이 되어 또 어긋난다(구체적인 것을 앞에 둔다).

**아직 안 한 것:** 3차 끝에서만 부른다(CLI `--backtranslate`). 1차 직후에도 부를 수
있으나 회차가 하나 더 늘어 시간이 두 배가 되므로, 실사용에서 값을 재 본 뒤 정한다.

### ~~T8. 차수 수렴 조건~~ 〔끝남〕

"완벽해지는 지점까지"를 기계가 알아야 멈춘다. **모델이 고치기를 멈추는 것으로는
안 된다** — LLM은 미사여구를 영원히 만진다.

```
멈춘다 = 층1 오역 플래그 0건
       AND 규정 위반 0건 (글자 수·리딩스피드·줄바꿈)
       AND 이번 차수의 변경이 임계 이하
       OR  차수 상한 도달 (시간 보호)
```

**멈춘 이유를 기록한다.** "5차에서 멈췄다"만으로는 완성인지 상한에 걸린 건지 모른다.

~~알려진 위험~~ **막았다.** `revise(baseline=...)`로 1차 대비를 함께 잰다. 실측:
가드 없이 3회차 돌면 2.70배, 가드 켜면 1.40배에서 멈춘다. 되돌릴 때는 **1차가 아니라
직전을 지킨다** — 중간 회차가 제대로 고친 것을 버릴 이유가 없다.

**수렴은 "고친 개수"로 끊는다.** 모델이 만지기를 멈추는 것을 기다리면 안 된다(LLM은
미사여구를 영원히 만진다). `rounds`가 최소, `max_rounds`가 상한이고 그 사이에서
`settle_at` 이하로 잠잠해지면 멈춘다. **최소 회차는 반드시 채운다** — 2차를 안 돌면
오역·용어를 아무도 보지 않는다.

**아직 안 넣은 조건:** 규정 위반 0건, 오역 플래그 0건. 회차마다 검사를 돌리는 것은
공짜지만(LLM 안 씀) 실사용에서 값을 재 본 뒤 넣는다 — 위반이 0이 되지 않는 자막도
있어서 그것만으로 끊으면 늘 상한까지 돈다.

### ~~T9. `.work/` 중간 산출물 + manifest~~ 〔끝남〕

지금 CLI는 `.source.srt`/`.draft.srt`/`.notes.srt`/`.review.srt`/`.ko.srt`/`.fixed.srt`로
파편적이고, **GUI는 아무것도 남기지 않는다**(메모리에서만 돈다). 15분 돌린 번역이
3차에서 깨지면 처음부터다.

```
<영상이름>.work/
    manifest.json          단계별: 모델, 시각, 소요, 바뀐 줄, 위반, 멈춘 이유
    01-generate.srt        타임코드 확정본 (이후 전 단계에서 불변)
    01-source.json         번호→원문 (감수가 오역 보려면 필수)
    02-first.srt
    03-revise-1.srt        회차마다 별도 파일
    03-revise-2.srt
    04-polish.srt
```

지킬 것: 원본을 덮어쓰지 않는다(규칙 7), `01-generate.srt`의 타임코드는 이후 불변
(각 단계 끝에 `--lock-timecodes` 검증), 전부 로컬.

실제로 나오는 것:

```
ep01.work/
    manifest.json      단계별 모델·시각·걸린 시간·바뀐 줄·역할
    01-source.json     번호별 원문
    02-first.srt
    03-revise-2차.srt
    03-revise-3차.srt
```

`Work.last()`가 마지막 단계와 그 자막을 준다 — **여기서 이어 하면 된다.**
`work.diff(a, b)`로 회차를 견준다.

**아직 안 한 것:** 이어 하기를 UI/CLI 명령으로 노출하지 않았다. 지금은 `.work/` 안의
`.srt`를 열면 되지만, `--resume` 같은 것이 있으면 더 낫다. 그리고 `stage_generate`
경로(전사)는 아직 남기지 않는다 — 번역이 가장 비싼 자리라 거기부터 했다.

### ~~T10. UI에 단계 노출~~ 〔끝남〕

`STAGES`에 `track` 필드를 추가해 번역 트랙과 한국어 트랙을 가른다. `Stage.available()`
/`_refresh_stages()`/`_stage_guard()` 기계장치는 이미 있으니 **데이터만 늘리면
버튼이 생긴다.**

둘 다 넣었다. 실제 모습:

```
소재     [자막 만들기]
번역     [① 1차 번역] [② 번역 감수] 회차[2] [③ 자막 윤문·QA]
         ① 1차 번역 끝 · 자막 2개 · 확인이 필요한 자리 1곳 → 다음은 [② 번역 감수]
한국어   [② 한국어 교정] [③ 자막 QA]
조사     [용어표] [캐릭터 문서]
```

**1차 번역이 이제 1차만 한다.** 전에는 체크박스 하나로 1~3차를 한꺼번에 돌려 단계
사이에 검토할 자리가 없었다.

**아직 안 한 것:** 도구 모음의 `만들 때 번역까지` 체크박스는 남겼다(생성과 번역을
한 번에 하고 싶은 경우가 실제로 있다). 줄기를 `종류`(sdh/translation)에 따라 숨기지
않았다 — 한국어 자막인데 종류가 `translation`인 경우가 있어 짐작하면 틀린다.

### ~~T11. 편집 기능 정리~~ 〔조사 끝 — **지울 것이 없었다**〕

여기 후보로 적어 둔 둘을 실제로 열어 보니 **둘 다 지울 근거가 없다.** 추측으로 적은

믿을 수 있는 신호(아무도 import하지 않는 모듈)만 보니 하나가 나왔다 — 아래 §4.

## 4. 결정 대기 / 확인 필요

- **`checker/mixer.py`가 고아다.** 아무도 import하지 않고 시험도 문서도 없다. 지우기
  전에 물어야 한다 — 독스트링에 **아직 안 해 본 좋은 설계**가 담겨 있다(VAD 정확도를
  재려면 정답이 필요한데, 깨끗한 말소리에 음악·잡음을 **섞으면** 정답이 공짜로 나온다.
  우리 휴리스틱에서 정답을 뽑는 순환이 아니다).
  다만 `runner.py`에서 배운 것이 있다: **아무도 안 쓰는 파일은 자기 목적을 못 한다.**
  쓸지 지울지 정해야 한다.

## 6. 되풀이하지 말 것 (실제로 당한 것들)

- **`python3 tests/run_tests.py > /dev/null && git commit`** 꼴로 잇는다. 파이프
  (`| tail`)는 종료 코드를 가리고 세미콜론(`;`)은 실패해도 다음 줄을 실행한다.
  둘 다로 실패한 테스트를 커밋한 적이 있다 — **세 번**이다.
- **시험 결과 출력은 파일 맨 끝에 둔다.** 앞에 두었다가 마지막 세 건이 실패해도
  보고되지 않는 상태로 한동안 있었다.
- **cmd.exe에 한글 인수를 직접 넘기지 않는다.** `--input` JSON 파일, `-F` 메시지
  파일, heredoc으로 쓴 `.py`를 쓴다.
- **평가셋은 문장까지 그대로 옮긴다.** 로그의 판정을 내가 지어낸 문장에 옮겨 붙여
  가짜 정답을 만든 적이 있다(사용자가 잡았다).
- **`%APPDATA%\자막편집기\` 폴더명과 `SUBTITLE_EDITOR_HOME` 환경변수는 공개
  계약이라 이름을 바꾸지 않는다.** 바꿨다가 시험 2건이 깨졌다.
- **자료가 없는 프로파일·임계값을 추측해서 만들지 않는다.**
- **시험이 사용자의 앱 로그에 쓴다.** `%APPDATA%\자막편집기\log.txt`에 `_Tiny 시작`,
  `배치: spotting` 같은 줄이 있으면 시험이 남긴 것이다 — 실사용 기록으로 오해하면
  엉뚱한 것을 조사한다. 실제로 두 번 헛짚었다.
- **로그를 두 곳에서 쓰지 않는다.** `Job.say`(일하는 실)와 `_note`(UI 실)가 같은 줄을
  각각 남겨 로그가 두 벌로 섞였다. 멈춤 조사에서 잘못 읽을 뻔했다. 지금은 일하는
  실에서만 남긴다(`_note_ui`가 화면 전용).
