## 3. 완료

1. **분리** (`separate.py`): 02:00~04:00을 44.1kHz 스테레오로 뽑아 10초 조각·1초 겹침으로 Demucs를 돌림. 120.000초 정확히 나옴.
2. **1차 음성 TC** (`voice_tc.py`):
   - Silero VAD(faster-whisper 동봉 v6)로 말소리 구간을 잡음
   - 5ms 파형 포락선으로 경계를 다시 잡음
   - VAD가 못 가르는 40~80ms 끊김(골짜기)은 whisper 낱말 경계와 맞을 때만 가름
   - VAD가 놓친 말 4곳은 whisper 낱말로 되살림
3. **텍스트 단위로 다시 끊기** (`retime.py` + `units.json`):
   - 1차 결과는 끊는 자리가 뜻과 어긋났음(한 문장 끝 낱말이 다음 자막으로 넘어감)
   - 방송 화면 자막 단위로 44개를 정하고, 인점은 표에 명시한 값을 씀(근거: 1차/파형/불확실)
4. **음성 끝** (`retime.py`의 `offset`):
   - 처음 방식(최고치 −35dB, 바닥 −45dBFS)은 잔소리까지 말로 봐 아웃점이 최대 3.5초 늦었다
   - 지금 방식: −25dB/−38dBFS, 0.35초 넘게 조용하면 끝. 음성 트랙에 샌 총소리(181.5초)를 말로 안 본다
5. **규칙** (`rules_frames.py`): 전부 프레임 정수로, 단계마다 자막 전체를 돈다.
   - 인점 = 음성 시작 3프레임 전, 아웃점 = 음성 끝 7프레임 뒤(`작업 기본 원칙` 600~604행)
   - 겹치면 다음 인점 우선, 최소 길이 25프레임 우선
   - 0.5초(15프레임) 미만 간격은 메운 뒤 2프레임. 메우다 전환을 넘으면 전환 −2프레임에서 멈춤
   - 장면전환 앞뒤 15프레임: 인점은 전환에 붙이거나 15프레임 이상, 아웃점은 전환 −2프레임이거나 15프레임 이상. 둘 중 덜 움직이는 쪽
   - 모든 전환을 동시에 만족하는 값만 후보(13프레임 간격으로 붙은 전환 5331·5344 사례)
6. **SE 확인**: 원본 영상 하드링크 `final_sdh.mp4` + `final_sdh.srt`로 열어 14개 화면 캡처(`se_capture.ps1`).
   - 여기서 #10~#12 아웃점이 전환 0.5초 앞에서 끊긴 오류를 찾아 고쳤다(5번 "단계마다 전체" 이유).

## 7. 주의 (gotcha)

- **규칙은 `작업 기본 원칙`을 따른다.** 장면전환 앞뒤 0.5초 전부, 인점 2~3프레임 전, 아웃점 6~9프레임 뒤. 좁힌 판(`tc_rules_nf.py`)을 쓰지 않는다.
- **규칙은 프레임 정수로 계산한다.** 밀리초로 하면 반올림 때문에 전환 1프레임 앞뒤로 어긋난다(`tc_rules_gdocs.py`로 돌렸을 때 #27·#30).
- **규칙은 단계마다 자막 전체를 돈다**(인점 → 간격 → 아웃점 → 최소 길이). 자막 하나씩 네 단계를 다 하면 다음 인점이 전환에 붙기 전에 앞 아웃점을 정해 버린다.
- **인점 자동 재탐색을 쓰지 않는다.** 앞말이 이어지는 곳에서 탐색 창 시작점을 인점으로 잡는다(130.040초 사례). 탐색 방식을 바꾸면 한 곳이 고쳐지고 다른 곳이 틀어졌다. 인점은 `units.json`에 값과 근거로 적는다.
- **정답 인점에 맞춰 값을 고치지 않는다.** 정답은 검증용이다. 맞추면 정답을 베끼는 것이다.
- 음성 트랙에도 총소리 같은 충격음이 샌다(Demucs 한계, 172~185초 스펙트로그램으로 확인). 음성 끝을 잡을 때 0.35초 넘는 쉼 뒤 소리는 말로 보지 않는다.
- whisper 낱말 시각은 수백 ms 어긋난다. 경계 위치는 파형이 정하고, 낱말은 "여기가 낱말 사이인가"만 본다.
- `torchaudio.save`는 이 PC에 백엔드(soundfile)가 없어 실패한다. `scipy.io.wavfile`로 쓴다.
- **SE를 실제 마우스로 조작하지 않는다.** Claude 앱 창이 SE 위에 겹쳐 있어 클릭이 사용자 창에 떨어진다. `se_capture.ps1`(PostMessage·BM_CLICK·PrintWindow)을 쓴다.
- SE를 **최소화 상태로 띄우면 같은 이름 영상 자동 열기가 안 된다.** 일반 창으로 띄운 뒤 `SetWindowPos`(활성화 없음)로 크기만 키운다.
- SE 목록 줄만 바꾸면 파형이 안 움직인다. "자막 위치로 이동" 버튼에 클릭 메시지를 보낸다.
- 셸 명령에 `Remove-Item`과 `"C:\Program Files\..."` 경로가 같이 있으면 훅이 명령 전체를 막는다. 캡처 파일은 새 이름으로 쓴다.
- 대사가 든 파일(`units.json`, SRT)은 공개 저장소에 올리지 않는다. 문서에서는 자막 번호로만 가리킨다.

- 소리 시작 탐지는 조용한 앞이 있는 4건만 잡혔다. 음악·연속 발화 구간은 판독하지 못했다.

## 9. 두 번째 구간 검증 (2026-10-01, E01 04:00~06:00, 초안 46개 대 사용자 수정 45개)

- 방법: 8절 기준(인점 = 소리 오름, 아웃점 = 말 끝 + 8프레임)을 적용한 초안을 사용자가 고치기 전에 만들고, 사용자 수정본과 45쌍을 맞췄다.
- 주의: 사용자가 초안 파일을 덮어써서 원본이 사라졌다. 초안은 중간 저장본에 같은 규칙을 다시 적용해 복원했다(`draft_0406_mine.srt`).

### 결과 (사용자 수정과의 일치, 자막 45쌍)

| 지표 | 화면 글자만(fix7) | 학습 기준 적용 초안 |
|---|---|---|
| 인점 ±1프레임(34ms) 이내 | 37 | 36 |
| 인점 ±100ms 이내 | 40 | 40 |
| 아웃점 ±1프레임 이내 | 31 | 35 |
| 아웃점 ±100ms 이내 | 36 | 39 |

- 사용자가 실제로 바꾼 것: 인점 21개, 아웃점 12개. 초안 #16은 앞 자막(#15)에 합쳐 삭제.

### 판정

- **인점 = 소리 오름: 유지.** 조용한 앞이 있는 6건에서 사용자 인점이 소리 오름보다 −10~−48ms(중앙값 −10ms). 8절과 일치한다. 다만 화면 글자만 쓴 판보다 나아지지 않았다(37대 36).
- **아웃점 = 말 끝 + 8프레임: 확인 안 됨.** 사용자 아웃점의 말 끝 뒤 지연이 중앙값 172ms, 사분위 1~277ms로 퍼져 있다(23건). 8절의 278ms(20건)와 다르다. 규칙으로 못 박을 수 없다.
- 아웃점 개선(31에서 35)은 대부분 장면전환 규칙 적용(3곳)에서 나왔다.
- 큰 어긋남은 분할·병합 판단이다: #13 아웃 +707ms, #15 아웃 +700ms(#16을 흡수), #39 아웃 +573ms, #8 인 +241ms, #43 인 −200ms. 음성 트랙으로는 알 수 없는 뜻 단위 판단이다.

### 결론

- 두 구간 모두에서 음성 트랙이 도움을 주는 것은 **인점**뿐이다. 아웃점과 자막 분할은 화면 글자·뜻·장면전환이 정한다.
- `rules/`에는 아무것도 승격하지 않는다. 인점 기준(소리 오름 −10ms 안팎)만 두 구간 8~10건이 같은 방향이지만, 표본이 작고 화면 글자 방식과 차이가 없다.

## 10. 파이프라인 방침 (2026-10-01, 8·9절 결과에 따름)

### 영상 종류별로 쓰는 신호

| 영상 | 인점 | 아웃점 | 자막 끊기·텍스트 |
|---|---|---|---|
| 하드섭(화면 글자 있음) | 화면 글자 프레임 + 음성 소리 오름으로 보정 | 화면 글자 프레임, 장면전환 규칙 | 화면 글자 |
| 화면 글자 없음 | 음성 소리 오름(−10ms 안팎) | 음성 말 끝 + 6~9프레임(미확인, 사람 확인) | 전사 + 사람 판단 |

- 하드섭 영상에서는 음성 분리를 새로 돌리지 않는다. 화면 글자가 정답지라서 음성은 인점 보정 외에 더할 것이 없다(9절).
- 음성 분리는 화면 글자가 없는 영상에서만 가치가 있다. 그때도 인점에만 쓴다.

### 규칙 우선순위 (사용자 지시, 2026-10-01)

- 인점 > 아웃점, 장면전환 > 아웃점.
- 인점 대 장면전환: 인점 우선(사용자 수정 #16·#24로 확인).
- 아웃점이 장면전환과 부딪히면 "전환 2프레임 전"을 먼저 고른다(0.5초 뒤보다 화면 글자 끝에 가깝다).
- 자막 사이 간격은 강제하지 않는다. 지시가 있을 때만 적용한다.

### 지켜야 할 작업 절차

1. **SE에서 파형을 확인한다(필수).** `se_capture.ps1`과 같은 방식으로 내가 띄운 SE만 쓴다. 44개 캡처 절차를 반복 스크립트로 만들면 3분 안에 끝난다.
2. **사용자에게 보내는 파일은 사용자가 덮어써도 원본이 남게 한다.** 보낸 파일의 복사본을 `_sent` 이름으로 남긴다. 9/30~10/1 사이 두 번, 사용자 수정이 내 파일을 덮어써서 비교 원본을 복원해야 했다.
3. 사용자 수정본과 비교할 때는 자막 번호가 아니라 **시간과 텍스트로 짝을 짓는다**(자막이 합쳐지거나 삭제될 수 있다).
4. 소리 오름 탐지는 조용한 앞이 있을 때만 믿는다. 음악·연속 발화 구간은 판독 불가로 표시하고 사람이 본다.

### 남은 일 (갱신)

1. **[사용자] 세 번째 구간이나 다른 작품에서 인점 기준(소리 오름 −10ms 안팎)을 확인한다.** 2편째까지 같은 방향이었다. 3편째까지 유지되면 규칙 11의 승격 보고를 한다.
2. 아웃점 규칙은 승격하지 않는다. 지연이 구간마다 다르다(278ms, 172ms).
3. SDH 효과음·화자명은 여전히 안 했다(5절). 효과음은 음성 트랙에 없으므로 `others.wav` 분석이 필요하다.
4. `checker/` 통합은 하지 않는다. 화면 글자가 없는 영상용 인점 보정만 통합 후보이고, 통합할 때 `tests/run_tests.py`에 시험을 넣는다(규칙 9).

## 11. 다른 PC에서 이어 하기 (2026-10-01)

### 데이터는 옮기지 않아도 된다

- 두 구간(02:00~04:00, 04:00~06:00)은 **학습용 시험**이었고 결론은 8~10절에 있다. 영상·wav·SRT는 결론을 다시 만들 때만 필요하다.
- 결론을 재현하는 숫자 기록은 git에 있다(대사 없음, 시각만).
  - `docs/evidence/voice_sep_user_edits_e01.csv`: 자막별 화면 글자 판·초안·사용자 수정본의 인점·아웃점(89행)
  - `tools/voice_sep_proto/compare_edits.py`: 위 CSV로 일치율 표를 다시 낸다
  - 확인: `python tools/voice_sep_proto/compare_edits.py docs/evidence/voice_sep_user_edits_e01.csv` 결과가 9절 표와 같아야 한다.
- 옮기지 **않는** 것: 영상, `voice.wav`·`others.wav`·`mix.wav`, 대사가 든 SRT. 공개 저장소에 올리지 않는다.

### 새 구간(세 번째)을 검증하려면 필요한 것

- E01 영상(또는 다른 하드섭 영상)과 그 영상의 화면 글자 기반 초안(`fix7` 방식). 이것들은 그 PC에서 새로 만들거나 그 영상만 복사한다.
- 화면 글자 없는 영상이라면 영상만 있으면 된다.

### 새 PC 준비

단계별 명령은 `README.md`의 "새 PC에서 시작하기"에 있다. 요약:

1. GitHub SSH 키 등록(`ssh -T git@github.com`으로 확인). 없으면 HTTPS 주소와 `gh auth login`.
2. `git clone git@github.com:tigermorning/subtitle-tc-generator.git` (`master`를 받는다. 작업 브랜치 `voice-sep-tc`는 병합 후 삭제했다)

4. `git config core.hooksPath tools/hooks`
5. 환경: 파이썬 + `torch`(CUDA), `torchaudio`, `scipy`, `numpy`, `ffmpeg`, Subtitle Edit. 음성 분리는 GPU가 필요하다(RTX 3060 Ti에서 2분 구간 1분 안팎).
