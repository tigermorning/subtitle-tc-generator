# 상용화 전 확인 목록

전제: 한국어 교정기와 자막 및 TC 생성기를 **판매할 제품**으로 만든다. 혼자 쓰는 도구와
파는 물건은 지켜야 할 것이 다르다. 아래는 코드보다 먼저 막힐 수 있는 것들이다.

작성일: 2026-08-11 (사용자가 상용화 계획을 밝힌 시점)

---

## 1. 법적으로 먼저 풀어야 할 것 — 여기서 막히면 코드가 소용없다

### 1.1 국립국어원 오픈 API의 상업적 이용 ⚠️ 최우선

교정기의 근거가 표준국어대사전·우리말샘·어문규범 API다. **판정의 핵심이 여기 있다.**

- 확인할 것: 각 API 이용약관의 상업적 이용 허용 여부, 호출 한도, 재배포 조건,
  출처 표시 의무
- 막힐 경우의 대안: 사용자가 **자기 API 키**를 넣게 한다(우리가 대행 호출하지 않는다).
  지금 구조가 이미 `.env`의 키를 쓰므로 그대로 간다
- 절대 하면 안 되는 것: 사전 데이터를 내려받아 제품에 동봉하는 것

### 1.2 kiwipiepy(형태소 분석기) 라이선스

교정기가 의존한다. 배포 형태(동봉/사용자 설치)에 따라 의무가 달라진다.
- 확인할 것: 라이선스 종류, 정적/동적 링크 구분, 고지 의무
- 같이 확인: 교정기의 나머지 의존성 전부(`requirements.txt`)

### 1.3 넷플릭스 가이드 내용의 재배포

`rules/sources/*.md`에 규정을 상세히 정리해 두었다. **개인 참고와 제품 동봉은 다르다.**

- 수치(16자, 12 CPS)와 조항 번호는 **사실**에 가까워 저작권 보호가 약하다
- 문장과 구조를 옮긴 요약본은 **2차 저작물**로 볼 여지가 있다
- 대응: 상용 배포판에는 `rules/sources/`를 넣지 않는다. 프로파일에는 수치·조항 번호·
  **원문 링크**만 남긴다. 지금 구조가 이미 데이터(`rules/*/*.yaml`)와 문서(`sources/`)로
  갈려 있어 그대로 뺄 수 있다
- 제품 문구에 "넷플릭스 공인"처럼 오해를 살 표현을 쓰지 않는다

### 1.4 SubtitleEdit(MIT)

파생·상용 배포 모두 가능하다. 저작권 고지만 유지한다. 다만 번들되는 ffmpeg·Tesseract·
hunspell 사전·Whisper 모델은 각자 라이선스가 다르므로 **동봉할 것만** 따로 확인한다.

### 1.5 고객 자막의 비밀 유지

번역가는 미공개 콘텐츠를 다룬다. 제품이 원고를 외부로 보내면 계약 위반을 유발한다.
- 지금 설계가 로컬 처리라 유리하다. **이 성질을 문서로 약속**하고 지킨다
- 오류 리포팅·사용 통계를 넣더라도 **자막 본문은 절대 보내지 않는다**
- 국립국어원 API 호출은 낱말 단위이지만 그래도 외부 전송이다 — 약관과 함께 고지한다

## 2. 제품이 되려면 필요한 것 (코드 밖)

- 설치 관리자(파이썬·모델·의존성 포함) — 지금은 파이썬을 아는 사람만 쓸 수 있다
- 갱신 경로: **규정 개정이 곧 제품 가치다.** 프로파일만 갱신하는 통로를 만든다
  (`rules/`를 코드와 분리해 둔 이유가 여기서 값을 한다)
- 라이선스 키·결제, 환불 기준
- 오류 보고(자막 본문 제외), 진단 로그
- 사용 설명서, 발주처 프로파일 만드는 법
- 지원 창구와 응답 기준

## 3. 규정 최신성 — 파는 물건의 책임

혼자 쓸 때는 "낡았네" 하고 넘기지만, 팔면 **틀린 기준으로 검사해 납품 사고가 나는** 문제가 된다.

지금 갖춘 것: 프로파일마다 `source.revision`(원문 개정일)과 `verified`(우리가 확인한 날).
필요한 것: 정기 확인 절차와 그 결과의 배포. 최소 분기 1회.

확인 대상(2026-08-11 기준 최신 개정일):

| 문서 | 개정일 | 프로파일 |
|---|---|---|
| Korean TTSG (번역 + SDH) | 2025-07-07 | ko-translation, ko-sdh |
| English (USA) TTSG | 2025-12-19 | en-translation, en-sdh |
| General Requirements | 2022-10-07 | common |
| Subtitle Templates | 2024-06-28 | en-template |
| Product Supplemental & Marketing | 2026-06-29 | (프로파일 없음) |
| KNP Sensitive Terminology | 2022-11-30 | (프로파일 없음) |
| 오디오 화면 해설 v2.5 | 2023-04-27 | (해당 없음) |

## 4. 기능 공백 — 파는 물건 기준으로 다시 본 것

- **디즈니+·쿠팡플레이 — 공식 문건 미확보**(2026-08-14 갱신). 프로파일 자체는 SDH·번역
  둘 다 있다. 작업자 실무 자료에서 나온 것이라 `official: false`이고 규칙 수가 적다.
  **파는 물건에서 이 구분이 중요하다** — "디즈니 기준으로 검사했다"고 말하려면 공식
  문건이 있어야 한다. 지금 리포트는 근거와 개정일을 머리에 찍어 구분하고 있다.
  벤더·파트너 경로로 공식 문건을 확보하는 것이 사업 과제다
- **작업 종류 선택**(본편 / 마케팅 자산 / 부가 자산). 마케팅 자산에 본편 기준을 적용하면
  속도·시간 지적이 전부 오탐이다
- **사용자 용어집**. KNP 같은 민감 용어 판정은 우리가 목록을 들면 위험하다. 사용자가
  자기 목록을 넣는 자리를 준다
- ~~**SE 4.x 지원.**~~ 〔끝남, 2026-08-11〕 4.x용 C# DLL(`plugin/se4/`)을 만들어 실제
  SE에 설치·동작 확인했다. SE5용 JSON 어댑터(`checker/plugin.py`)도 함께 유지한다
- 미구현 검사(픽셀 폭, 통화 환산, 글리프, 삐 처리 음절 수, 문장 분할)

## 5. 지금 당장의 결론

법률 확인 셋(**국립국어원 API 상업적 이용**, **kiwipiepy 라이선스**, **가이드 재배포**)이
기능보다 먼저다. 특히 첫 번째가 막히면 교정기의 판정 근거 구조를 바꿔야 하므로,
기능을 더 쌓기 전에 확인하는 편이 싸다.
