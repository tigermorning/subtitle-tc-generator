# 에이전트(Claude) 작업 오류 기록

이 문서는 코드 버그(`docs/HANDOFF.md` 6절)가 아니라 **작업 과정에서 에이전트가
반복한 실수**를 기록한다. 목적은 같은 팀(사람이든 다른 에이전트든)이 같은 자리에서
같은 실수를 또 하지 않는 것이다. 사용자가 지적한 순간·정확한 지적 내용·실제로
어떻게 고쳤는지(파일·메커니즘)를 남긴다 — "다음엔 조심하겠다"는 다짐이 아니라
**구조적으로 재발을 막은 지점**을 남기는 게 핵심이다.

새 항목을 추가할 때는 이 형식을 따른다: 무엇을 지적받았나 → 원인 → 실제 고침
(파일 경로 명시) → 재발 방지 메커니즘.

---

## 2026-08-29

### 1. 이미 고친 버그를 "안 고쳐졌다"고 다시 진단함

**무엇을 지적받았나**: 예능A 15회 SDH 초안이 정답과 구조적으로 안 맞는
문제(화자 바뀌어도 계속 이어붙임)를 처음부터 재진단했다 — whisper 재전사
2회, gap/duration 스윕 스크립트를 새로 짬. 그런데 `rules/genre/variety.yaml`에
**2026-08-27에 이미** `merge_max_ms: 2000`으로 고쳐져 있었고, 이유는 그
초안이 `--genre variety` 플래그 없이 생성됐기 때문이었다. 코드 버그가
아니라 플래그 누락이었다.

**원인**: 진단을 시작하기 전에 `docs/HANDOFF.md` 6절("그동안 찾아 고친
구조적 버그")과 `rules/genre/`를 먼저 확인하지 않았다. 근거가 이미 파일에
있었는데 안 보고 새로 판단했다.

**실제로 어떻게 고쳤나**:
- `.claude/skills/정답지-대조-진단/SKILL.md`에 "0. 시작 전에" 절 추가 —
  전사·스윕부터 손대지 않고 `docs/HANDOFF.md` 6절·`rules/genre`·
  `rules/learned`를 먼저 grep하도록 못박음
- `docs/corpus_status.yaml` 신설 — 작품/회차별 파이프라인 진행 상태를
  한 파일에 기록(아래 3번과 공유하는 인프라)

**재발 방지 메커니즘**: `CLAUDE.md` 규칙 17(아래 참고)이 이 스킬 문구를
프로젝트 전체 규칙으로 승격했다.

### 2. 이미 완성돼 전달한 파일을 "미완성 초안"으로 오판함

**무엇을 지적받았나**: 세션 시작 시점에 `.tmp/최종초안/예능A_15회_...초안.srt`를
"손교정 안 된 초안"이라고 답했다. 실제로는 어젯밤(2026-08-28) 세션이 3차
윤문 + 용어 고정("토크의 신")까지 끝내 `SendUserFile`로 이미 전달한
완성본(`polished.srt`)과 **바이트 단위로 동일한 파일**이었다 — `diff` 결과
차이 0.

**원인**: 파일 하나만 보고 그 파일의 이력(어느 세션이 언제 무슨 처리를
했는지)을 확인하지 않은 채 "생성기 원본 그대로"라고 단정했다. 세션 내
메모리(`project_learning_workflow.md`)의 오래된 문구만 보고, 그 뒤에 실제로
일어난 일(같은 세션 안에서 사용자가 "손교정"의 정의를 재정의하고 3차 윤문을
"손교정"으로 인정한 것)은 확인하지 않았다.

**실제로 어떻게 고쳤나**:
- `mcp__ccd_session_mgmt__search_session_transcripts`·`list_events`로 어젯밤
  세션의 실제 대화·명령을 직접 열어 확인 — 짐작이 아니라 원문 대조로 검증함
- `docs/corpus_status.yaml`의 `pipeline.text_polished`·`delivered` 필드로
  "이 작품/회차가 어느 단계까지 끝났는지"를 파일 하나에 명시적으로 기록

**재발 방지 메커니즘**: 규칙 17의 확인 목록 2번("`docs/corpus_status.yaml`에서
해당 작품/회차 — 이미 끝난 단계인가")이 이 케이스를 정확히 겨냥한다.

### 3. `--genre variety` 플래그를 두 세션 연속 빠뜨림

**무엇을 지적받았나**: 직접적인 사용자 지적은 아니었지만, 세션 기록을
대조하다가 발견함 — 어젯밤(2026-08-28) 세션도, 오늘 세션도 예능A
15·16회를 생성할 때 `--genre variety`를 빠뜨렸다. "다음엔 안 잊는다"는
다짐이 세션 종료 후 사라지기 때문에 같은 실수가 반복됐다.

**원인**: 플래그를 사람(에이전트)이 매번 손으로 타이핑하는 절차 자체가
실수하기 쉬운 구조였다. "기억력" 문제가 아니라 "매번 손으로 조립한다"는
프로세스의 결함이었다.

**실제로 어떻게 고쳤나**:
- `tools/gen_from_ledger.py` 신설 — `docs/corpus_status.yaml`에서
  platform·lang·kind·genre를 읽어 `--generate` 명령을 **자동 조립**한다.
  사람이 플래그를 다시 타이핑할 일이 없다.

**재발 방지 메커니즘**: 플래그 누락이라는 실수 **종류 자체**가 이 도구를
쓰는 한 구조적으로 불가능해진다 — "기억하기" 대신 "자동화"로 막음.

---

### 4. 사용자가 말하지 않은 내용을 "사용자 지시"로 기억하고 있었음

**무엇을 지적받았나**: 사용자 직접 인용(2026-08-29): "가끔 보면 내가
말하지 않은데요? 내가 지시하지 않은 내용을 네가 내가 지시했다고 기억하고
있더라고. 이런 환각 현상을 없애야 해. 내가 지시한 내용은 정확하게 기억하고
네가 지어내는 내용은 없어야 해." — `CLAUDE.md`와 메모 곳곳의 "(사용자
지시, 날짜)" 인용이 실제 발화가 아니라 과거 세션의 요약·추론이 사실처럼
굳어졌을 위험을 지적함.

**원인**: 근거의 출처(사용자 발화 자체)를 검증 없이 사실로 적어 넣는 습관 —
규칙 14의 poisoning(오염)과 같은 구조지만, 여기선 출처까지 지어내는 더
심각한 경우.

**실제로 어떻게 고쳤나**:
- 메모리 `feedback_no_fabricated_user_attribution.md` 신설(에이전트 개인
  메모리 — 이 리포와 별도로 세션 간 유지됨) — "사용자 지시"라고 적을 땐
  직접인용 위주로, 불확실하면 먼저 확인부터 받는다는 원칙을 남김
- 기존 `feedback_check_sources_before_claiming_gap.md`를 "규정 공백"뿐
  아니라 "코드 버그"·범위로 확장(1번 사고와 같은 결)

**재발 방지 메커니즘**: 완전한 감사(과거 12건의 "(사용자 지시, ...)" 인용
전부 원문 대조)는 아직 안 끝났다 — 이번 세션엔 표본(규칙 16의 한 건)만
직접 세션 기록으로 검증했고 실제 발화와 일치함을 확인했다. 나머지는 필요할
때마다 같은 방식(`search_session_transcripts`→`list_events`)으로 검증한다.

## 이 넷의 공통점

전부 원인이 같다: **근거가 이미 어딘가에 있는데(코드·이전 세션·사용자
발화) 확인하지 않고 새로 판단했다.** 그래서 개별 대응 대신 `CLAUDE.md`
규칙 17로 "손대기 전에 셋을 먼저 본다"(`docs/HANDOFF.md` 6절 ·
`docs/corpus_status.yaml` · 프로젝트 메모리)는 체크리스트를 만들었다 —
이 문서는 그 규칙이 왜 필요했는지의 근거 기록이다.
