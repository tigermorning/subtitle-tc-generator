# 에이전트(Claude) 작업 오류 기록

이 문서는 코드 버그(`docs/HANDOFF.md` 6절)가 아니라 **작업 과정에서 에이전트가
반복한 실수**를 기록한다. 목적은 같은 팀(사람이든 다른 에이전트든)이 같은 자리에서
같은 실수를 또 하지 않는 것이다. 사용자가 지적한 순간·정확한 지적 내용·실제로
어떻게 고쳤는지(파일·메커니즘)를 남긴다 — "다음엔 조심하겠다"는 다짐이 아니라
**구조적으로 재발을 막은 지점**을 남기는 게 핵심이다.

새 항목을 추가할 때는 이 형식을 따른다: 무엇을 지적받았나 → 원인 → 실제 고침
(파일 경로 명시) → 재발 방지 메커니즘.

## 2026-08-29

### 1. 이미 고친 버그를 "안 고쳐졌다"고 다시 진단함

**무엇을 지적받았나**: 예능A 15회 SDH 초안이 정답과 구조적으로 안 맞는
문제(화자 바뀌어도 계속 이어붙임)를 처음부터 재진단했다 — whisper 재전사
2회, gap/duration 스윕 스크립트를 새로 짬. 그런데 `rules/genre/variety.yaml`에
**2026-08-27에 이미** `merge_max_ms: 2000`으로 고쳐져 있었고, 이유는 그
초안이 `--genre variety` 플래그 없이 생성됐기 때문이었다. 코드 버그가
아니라 플래그 누락이었다.

**원인**: 진단을 시작하기 전에 `docs/HANDOFF.md` 6절("그동안 찾아 고친
구조적 버그")과 `rules/genre/`를 먼저 확인하지 않았다. 근거가 이미 파일에
있었는데 안 보고 새로 판단했다.

**실제로 어떻게 고쳤나**:

- `docs/corpus_status.yaml` 신설 — 작품/회차별 파이프라인 진행 상태를
  한 파일에 기록(아래 3번과 공유하는 인프라)

**재발 방지 메커니즘**: `CLAUDE.md` 규칙 17(아래 참고)이 이 스킬 문구를
프로젝트 전체 규칙으로 승격했다.

### 2. 이미 완성돼 전달한 파일을 "미완성 초안"으로 오판함

**무엇을 지적받았나**: 세션 시작 시점에 `.tmp/최종초안/예능A_15회_...초안.srt`를
"손교정 안 된 초안"이라고 답했다. 실제로는 어젯밤(2026-08-28) 세션이 3차
윤문 + 용어 고정("토크의 신")까지 끝내 `SendUserFile`로 이미 전달한
완성본(`polished.srt`)과 **바이트 단위로 동일한 파일**이었다 — `diff` 결과
차이 0.

**원인**: 파일 하나만 보고 그 파일의 이력(어느 세션이 언제 무슨 처리를
했는지)을 확인하지 않은 채 "생성기 원본 그대로"라고 단정했다. 세션 내
메모리(`project_learning_workflow.md`)의 오래된 문구만 보고, 그 뒤에 실제로
일어난 일(같은 세션 안에서 사용자가 "손교정"의 정의를 재정의하고 3차 윤문을
"손교정"으로 인정한 것)은 확인하지 않았다.

**실제로 어떻게 고쳤나**:
- `mcp__ccd_session_mgmt__search_session_transcripts`·`list_events`로 어젯밤
  세션의 실제 대화·명령을 직접 열어 확인 — 짐작이 아니라 원문 대조로 검증함

  "이 작품/회차가 어느 단계까지 끝났는지"를 파일 하나에 명시적으로 기록

**재발 방지 메커니즘**: 규칙 17의 확인 목록 2번("`docs/corpus_status.yaml`에서
해당 작품/회차 — 이미 끝난 단계인가")이 이 케이스를 정확히 겨냥한다.

### 3. `--genre variety` 플래그를 두 세션 연속 빠뜨림

**무엇을 지적받았나**: 직접적인 사용자 지적은 아니었지만, 세션 기록을
대조하다가 발견함 — 어젯밤(2026-08-28) 세션도, 오늘 세션도 예능A
15·16회를 생성할 때 `--genre variety`를 빠뜨렸다. "다음엔 안 잊는다"는
다짐이 세션 종료 후 사라지기 때문에 같은 실수가 반복됐다.

**원인**: 플래그를 사람(에이전트)이 매번 손으로 타이핑하는 절차 자체가
실수하기 쉬운 구조였다. "기억력" 문제가 아니라 "매번 손으로 조립한다"는
프로세스의 결함이었다.

**실제로 어떻게 고쳤나**:
- `tools/gen_from_ledger.py` 신설 — `docs/corpus_status.yaml`에서
  platform·lang·kind·genre를 읽어 `--generate` 명령을 **자동 조립**한다.
  사람이 플래그를 다시 타이핑할 일이 없다.

**재발 방지 메커니즘**: 플래그 누락이라는 실수 **종류 자체**가 이 도구를
쓰는 한 구조적으로 불가능해진다 — "기억하기" 대신 "자동화"로 막음.

굳어졌을 위험을 지적함.

**원인**: 근거의 출처(사용자 발화 자체)를 검증 없이 사실로 적어 넣는 습관 —

**실제로 어떻게 고쳤나**:

### 5. 정답지가 있는 영상에 "손교정·완성본 전달"을 계속함 — 애초에 필요 없는 일이었음

**무엇을 지적받았나**: 사용자 질문(2026-08-30): "정답지 있는 상황에서
손교정이라는 게 의미가 있어? 손교정이라는 것은 정답지 없는 상황에서...
억지로 학습하기 위해서 하려는 건데, 예능A 15·16회는 SRT 파일로 영어
번역도 있고 한국어 SDH도 있는데 이걸 굳이 왜 손교정을 해야 하는 거야?"

**원인**: 규칙 13이 이미 "정답지 대조는 도구(`checker/`) 검증용이지 이
영상 자체의 완성본을 만드는 게 목적이 아니다"라고 정의해 뒀는데, 실제
작업(2026-08-28 밤 + 2026-08-29 오늘)은 예능A 15·16회 초안을 3차
윤문까지 입혀 "완성본"으로 `SendUserFile`로 전달했다. **정답지가 이미
있는데** 그보다 못한 근사치를 만들어 전달한 것 — 목적(도구 검증)과 산출물
(영상별 완성 자막 전달)을 혼동했다. 다른 사고들과 달리 이건 "근거를 안
봐서"가 아니라 **작업의 목적 자체를 잘못 설정**한 경우다.

**실제로 어떻게 고쳤나**:
- `CLAUDE.md` 규칙 13에 문단 추가 — "정답지 있는 영상은 완성본을 만들어
  전달할 필요가 없다. 정답지 자체가 이미 완성본이다." 앞으로 정답지가
  이미 있는 언어·방향에는 생성·윤문·전달을 하지 않고, `--generate`+
  `--against`로 도구를 검증·수정하는 것까지만 함
- 이미 전달한 15·16회 "완성본" 파일은 되돌리지 않음(전달 자체를 취소할
  수 없고, 코드 검증에 실제로 쓰인 산출물이라 완전히 무의미하진 않았음) —
  다만 앞으로 같은 상황에서 반복하지 않음

**재발 방지 메커니즘**: `docs/corpus_status.yaml`에 `text_polished`·
`delivered` 단계가 아직 남아 있다 — 이 필드들은 **정답지가 없는 영상**
전용으로 좁혀 써야 한다(스키마 자체를 아직 안 고쳤음, 다음에 이
원장을 다시 쓸 때 이 구분을 필드로 명시할 것).

### 6. "할 일 없다"고 확언했는데 확인 안 한 것이었음 — 원장 스키마 자체가 불완전했음

**무엇을 지적받았나**: 5번 사고 직후 "예능A 15·16회는 이제 할 일
없다"고 말했다. 사용자가 바로 반박: "확인해 보니까 영어 번역 자막이
안 들어가 있고 한국어 SDH만 되어있던데 할 일이 없다는 건 거짓말 아니야?"
— 맞았다. `docs/corpus_status.yaml`을 만들 때 `kind: sdh` 하나만
모델링해서, 이미 정답지가 있던 영어 번역(`E15_영어_번역.srt`·
`E16_영어_번역.srt`) 자체가 원장에 없었다 — 원장을 봐도 "번역은 어떻게
됐나"를 물을 방법조차 없었다.

**같은 자리에서 사용자가 더 큰 규칙을 못박음**(직접 인용): "확인되지
않은 사실 또는 네가 잘 알지 못하는 사실에 대해서 가볍게 확언하지 마.
나는 아주 철저한 파트너를 원해." → 메모리 `feedback_no_casual_unverified_claims.md`로
저장.

**원인**: 원장(1번 사고에서 만든 도구)을 설계할 때 "이 작품에 정답지
kind가 여러 개일 수 있다"는 걸 검토 안 하고 하나만 가정했다 — 새 도구를
만들면서 **그 도구 자체에 검증되지 않은 가정을 심었다.**

**실제로 어떻게 고쳤나 — 확인하다가 실제 코드 버그 두 개를 더 찾음**:
- `docs/corpus_status.yaml`을 `schema_version: 2`로 바꿔 `episodes.<회차>.kinds.{sdh,translation}`
  구조로 재작성. `source_lang`(발화 언어)과 kind별 `lang`(결과물 언어)을
  분리 — 번역 kind는 이 둘이 다르다는 걸 처음엔 놓쳤다가 `tools/gen_from_ledger.py`를
  고치면서 발견해 바로잡음
- `tools/gen_from_ledger.py`에 `kind` 위치 인자 추가, `--translate` 자동
  포함, `--whisper-lang`엔 `source_lang`(발화 언어)을 쓰도록 수정 — 원래
  코드는 결과물 언어(`en`)를 whisper 언어로 잘못 넘길 뻔했다
- `tools/calibrate_regroup.py`를 새 스키마로 고쳐 실제로 돌려본 결과,
  번역 kind에서 `genuine_pairs()`(오늘 만든 함수)가 **한글이 없으면
  화면자막으로 오판**해서 영어 정답을 전부 걸러내는 버그를 발견 —
  `checker/evaluate.py`의 판정을 "한글도 영어 소문자도 없으면 캡션"으로
  일반화해 고침
- 고친 뒤 재실행하니 이번엔 "genuine=3"으로 나왔는데, 이것도 **가짜
  신호**였다(원시 한국어 전사와 영어 정답을 직접 비교한 거라 우연한
  코드스위칭 영어 단어 몇 개만 우연히 걸린 것) — `calibrate_regroup.py`가
  발화 언어와 정답 언어가 다른 kind는 아예 건너뛰도록 다시 고침(번역
  품질 검증은 이 가벼운 도구의 범위 밖이라고 명시)

**재발 방지 메커니즘**: 새 스키마 자체가 "kind 여러 개" 가능성을 구조로
표현하므로, 다음 작품을 등록할 때 kind 하나만 적어 넣는 실수가 나면 원장
읽는 사람(에이전트든 사람이든)이 다른 kind가 있는지부터 의심하게 된다.
근본적으로는 [[feedback_no_casual_unverified_claims]] — 도구를 "다
됐다"고 말하기 전에 실제로 다른 kind·다른 언어로 한 번 돌려보는 습관이
이 사고를 막는다.

### 7. 정답지 대조에 불필요한 자체 비교(ablation)를 끌어들임

**무엇을 지적받았나**: 예능A 15회 영어 번역을 오늘 코드(`--genre variety`)로
재생성한 뒤, "variety가 도움이 됐는지" 판단하려고 오늘 결과를 **2026-08-28
v12(12차 반복한 결과)와 비교**했다. 다듬은 횟수가 다른 두 결과를 대놓고
비교했으니 답이 안 나오는 게 당연했다. 사용자 지적(직접 인용): "네가 비교해야
할 것은 옛날에 내가 작업한 것과 오늘에 내가 작업한 것이 아니야. 너는 정답지를
보고 학습되는 것이기 때문에 네가 비교할 것은 네가 오늘 생성한 것과 정답지야."
그리고: "앞으로 이런 간단하고 당연한 지시 안 하고 싶어. 이런 대화는 시간
낭비야. 명확하게 어디에다 적어놔."

**원인**: 규칙 13(정답지 대조 = 도구 검증)의 핵심 절차를 다시 안 읽고 즉흥적으로
"공정 비교"라는 ML 실험 설계식 사고(A/B 테스트, 변수 통제)를 끌어왔다 — 이
프로젝트에서 정답지 대조는 원래 훨씬 단순하다: **오늘 만든 것을 정답지와
바로 대조하고, 어긋난 자리를 본다.** 그게 전부다.

## 공통점

1~4·6번은 원인이 같다: **근거가 이미 어딘가에 있는데(코드·이전 세션·
사용자 발화·다른 kind) 확인하지 않고 새로 판단했다.** 그래서 `CLAUDE.md`
규칙 17로 "손대기 전에 셋을 먼저 본다"(`docs/HANDOFF.md` 6절 ·
`docs/corpus_status.yaml` · 프로젝트 메모리)는 체크리스트를 만들었고,
6번을 계기로 "가볍게 확언하지 않는다"는 더 포괄적인 규칙이 하나 더
생겼다.

5번은 다른 결이다 — 근거를 안 본 게 아니라 **애초에 이 작업이 왜
필요한지(목적)를 정의한 규칙(13)을 매번 다시 안 물었다.** "정답지가
있으니 대조해서 도구를 고치자"까지는 맞았는데, 거기서 "그러니 이 영상의
완성본도 만들자"로 슬쩍 넘어간 게 문제였다. 이 문서는 세 종류의 실수를
구분해서 남긴다 — 근거 확인 누락(1·2·4·6), 목적 재확인 누락(5),
플래그 자동화가 필요한 반복 조작 실수(3).
