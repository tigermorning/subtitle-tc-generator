# 인수인계 — 하드섭 TC·자막 추출 (2026-09-25)

이 문서는 **하드섭 영상(자막이 화면에 구워진 영상)에서 TC와 자막을 뽑는 갈래**만 다룬다.
프로젝트 전체 지도는 `docs/HANDOFF.md`, 작업 규칙은 `CLAUDE.md`를 본다.

## 1. 목표

- 하드섭 영상(임베디드 자막 트랙 없음)에서 **자막 초안(SRT)** 을 뽑는다.
  - TC: 자막이 뜨는 인점·아웃점
  - 텍스트: 화면에 보이는 그대로(줄바꿈 포함)
- 결과는 **정답지가 아니라 초안**이다. 사람이 영상과 대조해 확정한 뒤에만
  `학습한 TC 및 자막 모음/`에 넣는다(`.claude/skills/정답지-학습/SKILL.md`).
- 기준 발주처: **넷플릭스** (사용자 확인, 2026-09-25). SDH라서 장면전환 규정을 적용한다.
- 사용자가 넓히려는 범위(아직 안 함):
  - 화면 자막이 1줄인지 2줄인지 보고 줄바꿈까지 재현
  - 화면 글자의 맞춤법·띄어쓰기 확인
  - Claude가 화면을 직접 읽어서 텍스트를 채우기

### 2-2. 탈락한 방법 (다시 시도하지 말 것)

| 방법 | 탈락 사유 |
|---|---|
| 12fps 전 프레임 OCR | 71분에 7~8시간. 프레임 시각을 `i * int(1000/12)`(83ms)로 계산해 뒤로 갈수록 TC가 앞당겨짐 |
| 경계만 따로 seek해서 정밀화 | ffmpeg이 짧은 구간 seek 시 다른 프레임을 줌 (BACKLOG T13에 기록) |
| 윤곽선 밀도로 경계 판정 | 배우 얼굴·옷깃에 반응 |
| 프레임 정확한 글자 출현 시각을 정답으로 보기 | 방송 글자 타이밍이 음성 시작점과 ±2프레임 어긋남. 사용자 기준은 음성 시작점 |
| SE ASS 10ms 반올림이 원인이라는 진단 | 틀림. 원인은 위 항목. 10ms 내림 표기는 그대로 유지 |
| 음성 시작점 탐색창 ±500ms | 앞뒤의 다른 소리를 잡아 결과가 흔들림. ±200ms 유지 |
| 구글 독스 양방향 규정(전환 0.5초 벌리기) | 이 작품은 음성 시작점 우선이라 채택 안 함. 코드는 `tc_rules_gdocs.py`에 남김(v4) |
| EasyOCR 전처리(확대, 글자만 남기기) | 오독이 거의 줄지 않음 |
| 시간추적자 설록 | 색 있는 예능 캡션이라 이 방식 대상이 아님 (`--ocr-scan`으로 처리) |

## 3. 적용 중인 TC 규정 (v6)

근거: 사용자 결정(2026-09-25) + SE 넷플릭스 프리셋 소스 확인.

- **음성 시작점 우선.** 인점의 기본값은 음성 에너지가 처음 올라오는 지점.
- **인점**: 장면전환 앞 7프레임(234ms) ~ 뒤 0.5초 안이면 전환 첫 프레임으로 붙임.
- **아웃점**: 장면전환 앞 0.5초 ~ 뒤 7프레임 안이면 전환 2프레임 전(70ms 전)으로 당김.
- **간격**: 0.5초 미만은 앞 자막 아웃점을 늘려 메운 뒤 70ms를 둠. 겹침 없음.
- 다음 자막의 음성이 전환 전에 시작하면 앞 자막은 전환에 못 맞춘다(음성 우선). 조정 기록에 남긴다.
- 장면전환은 **추정**이다(`CLAUDE.md` 규칙 4). 바꾼 값은 전부 `report.txt`에 남긴다.

출처 정리:
- SE 넷플릭스 프리셋: `subtitleedit-src/src/libse/Settings/BeautifyTimeCodesSettings.cs:87` — 인점 빨간 영역 7프레임, 초록 영역 12프레임, 아웃점 간격 2프레임
- SE 판정 로직: `subtitleedit-src/src/libse/Forms/TimeCodesBeautifier.cs:986` `FindBestCueFrame`
- 작업자 자료(구글 독스 사본): `rules/private/sources/작업자-자료/작업 기본 원칙.txt` 197~260행, 371~374행
- 넷플릭스 공식(방향 규칙): `checker/timing.py:463` 주석과 `rules/private/netflix/common.yaml:54`

주의할 차이:
- SE 프리셋의 초록 영역(7~12프레임 밖으로 밀기)은 **적용하지 않았다.** 음성 우선이라서.
- 기존 `checker/timing.py`의 `suggest_shot_snap`은 인점을 "전환 뒤"만, 아웃점을 "전환 앞"만 당긴다.
  v6은 인점 "전환 앞 7프레임", 아웃점 "전환 뒤 7프레임"도 당긴다. 통합 시 둘을 맞춘다.

## 7. 주의 (gotcha)

- TC를 검증할 때는 **SE 파형의 파란 선(음성 시작점)** 과 대조할 것. 글자가 뜬 프레임과 맞는지는 기준이 아니다.
- 음성 시작점 탐색창은 ±200ms로 둘 것. 넓히면 결과가 흔들린다.
- 장면전환 근처 규칙을 고칠 때는 파일에 **적히는 값(10ms 내림)** 으로 검증할 것. 내림 전 값으로 재면 "정확히 0.5초"가 0.49초로 바뀌는 것을 놓친다.
- 아웃점을 전환 2프레임 전으로 맞추는 값(`OUT_LEAD`)은 최소 간격(`GAP`, 70ms)과 같게 둘 것. 다르면 다음 자막이 전환에 붙었을 때 3ms 차이로 못 맞춘다.
- 간격 메우기(0.5초 미만)가 전환에 맞춘 아웃점을 다시 늘리지 않게 할 것 (`locked` 표시).
- `[읽기 실패]` 구간은 규칙 처리에서 **빼고**, 보고서에만 남길 것. 넣으면 앞 자막 아웃점이 가짜 자막까지 늘어난다.
- 화면 글자를 읽을 때 문맥으로 고쳐 쓰지 말 것. 보이는 그대로.
- 스크립트 이름을 `signal.py`처럼 표준 라이브러리 이름으로 짓지 말 것 (`subprocess`가 불러 순환 import로 죽는다).
- 한글 폴더명 `[습작]`을 `glob`에 넣지 말 것(`[...]`가 문자 클래스). `os.listdir`이나 정확한 경로를 쓴다.
- 백그라운드 실행은 도구의 `run_in_background`로 **스크립트를 직접** 돌릴 것. 셸 안의 `&`는 도구가 끝날 때 함께 죽거나, 고아 프로세스로 남아 폴더를 붙잡는다(`rm: Device or resource busy`).
- 셸 작업 디렉터리를 지울 폴더 안에 두지 말 것 (Windows에서 삭제가 안 된다).
- EasyOCR은 시스템 파이썬(torch 2.6.0+cu124, GPU)에 설치돼 있어 시제품은 그것으로 돈다. 기존 `checker/ocr.py`는 `.venv-ocr`를 요구한다. 통합할 때 정한다.
- 이 폴더의 SRT는 방송사 자막 텍스트를 담고 있다. `.work/`는 gitignore이므로 리포에 올리지 말 것.
- **미확인 가정**: 프레임 정확도는 E01(720p)과 유미의 세포들(1080p 앞 10분)에서만 봤다. 다른 해상도·다른 자막 스타일(색 자막, 두꺼운 외곽선)은 모른다.
