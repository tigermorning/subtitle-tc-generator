# 정답지 학습

`[습작] SDH+번역/`에 새로운 정답 영상(공식/전문가 자막이 붙은 시판·방영 영상)이
들어왔을 때 쓴다. `CLAUDE.md` 규칙 11·12와
`C:\Users\user\.claude\projects\...\memory\project_learning_workflow.md`가 정한
절차를 그대로 코드화한 것이다 — 산문을 매번 다시 읽고 재구성하지 않는다.

**정확히 다 훑는 것이 빠르게 끝내는 것보다 우선이다**(규칙 12). 여러 영상을 한
번에 몰아서 처리하지 않는다 — 한 영상을 끝까지 확인하고 다음으로 넘어간다.

## 0. 시작 전에 — CLAUDE.md 규칙 17

이 영상(작품/회차)을 손대기 전에 `CLAUDE.md` 규칙 17의 세 곳부터 확인한다:
`docs/HANDOFF.md` 6절, `docs/corpus_status.yaml`의 해당 항목, 이 프로젝트
메모리(`feedback_*`). 특히 `docs/corpus_status.yaml`에 이미 항목이 있고
`done: true`인 단계가 있으면 — 그 증거(생성 로그·`--against` 결과 등)부터
열어보고, 정말 다시 할 이유가 없으면 재실행하지 않는다. 작업이 끝나면
`docs/corpus_status.yaml`을 갱신한다(안 하면 다음 세션이 또 처음부터
판단하게 된다 — 2026-08-29 예능A 15·16회에서 실제로 두 번 겪음).

## 절차

### 1. 컨테이너 무결성부터 확인한다

```bash
ffprobe -v error -show_entries format=duration,size -of default=noprint_wrappers=1 <파일>
ffmpeg -v error -i <파일> -map 0:v:0 -f null - 2>&1 | head -30
```

- 헤더 확인만으론 부족하다 — `ffprobe -select_streams s`는 깨진 파일도 멀쩡해
  보일 수 있다. 반드시 전체 디코드 시도까지 한다.
- `invalid as first byte of an EBML number`, `h264 decode MB errors`가 파일 전반에
  걸쳐 나오면 손상이다. 재다운로드 전까지 이 영상은 학습하지 않는다(예능A 19회,
  Money Heist S04E01 사례 — 둘 다 이 단계에서 걸러졌다).

### 2. 발주처를 특정한다

트랙 제목·릴리스 그룹명·메타데이터에서 찾는다. 확실치 않으면 **추측하지 않고**
`platform: unknown` 버킷에 넣는다(2026-08-26 영화F 사례 — PVOD로
여러 곳에 동시 발매돼 특정 못 함). 나중에 실제 스트리밍처를 확인해 역으로 특정할
수도 있다.

### 3. `forced` 트랙은 예외 없이 제외한다

`tools/corpus_build.py`의 `pick()`이 트랙 disposition의 `forced` 플래그와 제목
문자열 둘 다로 거른다. 화면 속 다른 언어에만 뜨는 부분 자막이 전체 대사·SDH로
오인되면 학습값 전체가 반쪽짜리로 오염된다(사용자 지시, 2026-08-25 — 예외 없음).

### 4. 추출하고 100% 일치를 확인한다

```bash
python -m tools.corpus_build --video <파일> --lang <lang> [--sdh] [--target-title-hint <힌트>]
```

- 트랙이 여럿이고 제목이 없으면 `pick()`이 `None`을 돌려준다(추측 거부) — 이때는
  사용자에게 실제 플랫폼 화면 스크린샷으로 어느 트랙이 진짜인지 확인받는다
  (예능B 사례).
- **자료 형식이 이상해서(예: 일본어 롤업 자막) 원래 모양으로 재구성해야 하는
  경우는 재구성하지 않는다.** 겹치는 구간을 어느 쪽에 붙일지 판단이 들어가면
  그건 정답지에서 읽은 값이 아니라 기계가 지어낸 값이다 — 못 쓰는 것으로 남긴다.

### 5. `rules/learned/<platform>/<lang>-<kind>.yaml`에 기록한다

- `source.official: false`, `source.origin: learned`
- `source.from.작품`에 제목·형태·**공개(방영/출시) 연도**·표본 크기(줄_합계)를 적는다.
  연도가 없으면 나중에 "이 작업자 자료가 낡았는지" 판단할 근거가 없어진다(규칙 11).
- `lines.전체_대사자막`은 `stats_for()`의 `lines_sum`(한줄+두줄+세줄이상)을 쓴다.
  raw `cues`와 다르면 반드시 `lines_sum`을 검증하고 그 값을 쓴다 — 효과음 전용
  큐가 raw cues에는 섞여 있다.
- 같은 발주처의 기존 학습값과 값이 어긋나면: 여러 작품이 가리키는 값과 최신 작품
  하나가 다르면 **지적**으로 보고한다(자동 채택 아님). 최신 작품 쪽에 무게를
  싣되, 승격(공식 규정으로 굳히기)은 별도로 사람 확인을 거친다.
- **`rules/<platform>/`(공식 규정 파일)는 절대 고치지 않는다.** 학습값이 규정과
  충돌해도 규정이 이기는 게 아니라 애초에 겨루지 않는다.

### 6. 테스트 통과 확인 후 커밋한다

```bash
python3 tests/run_tests.py && git commit -m "..."
```

파이프(`| tail`)나 세미콜론(`;`)으로 이어 쓰지 않는다 — 종료 코드를 가리거나
실패해도 다음 줄이 실행된다(규칙 9, 세 번 뚫렸던 실수). `tools/hooks/pre-commit`이
이제 기계로 막아 주지만 습관은 그대로 유지한다.

### 7. 원자료를 이중 백업하고, 확정 srt를 정리한다

- `.tmp/corpus/`의 원자료를 로컬 백업 폴더 + 비공개 GitHub 저장소
  (`tigermorning/subtitle-corpus-backup`)에 커밋한다. 메인 저장소는 **공개**라
  저작권 있는 자막 원문을 그대로 올리면 안 된다(`.gitignore`로 막혀 있는지 확인).
- 정답지와 100% 일치를 확인한 srt만 원본 그대로(재작성·병합 없이)
  `학습한 TC 및 자막 모음/<발주처>_<작품>/`에 복사한다.
- 영상 파일은 **아래 "학습완료로 옮기기 전 기준"을 통과했을 때만**
  `[습작] SDH+번역/학습완료/`로 옮긴다(사용자가 나중에 용량 정리로 지울 수 있는
  임시 보관 — 확정 srt와는 다른 폴더, 절대 합치지 않는다). 기준 미달이면
  `[습작] SDH+번역/` 바로 밑(작업 대기)에 그대로 둔다.
- **옮길 때 생성기가 만든 srt도 원본 영상과 같이 넣는다**(사용자 지시,
  2026-08-27) — 사용자가 직접 대조해 보기 위해서다. 언어·방향별로 파일 하나씩
  (예: `E15_한국어_SDH_생성.srt`, `E15_영어_번역_생성.srt`), 원본 정답 srt와
  헷갈리지 않게 이름에 "생성"을 넣는다. 정답 srt 자체는 여전히
  `학습한 TC 및 자막 모음/`에만 있고 여기로 복사하지 않는다.

## 학습완료로 옮기기 전 기준 (사용자 지시, 2026-08-27)

이 프로젝트의 학습은 네 단계다 — **1) 목적**: 정답을 많이 학습해서 나중엔
정답 없이도 스스로 정답을 만들 수 있게 한다. **2) 정답 학습**: 원어가
한국어인 영상은 한국어 SDH·영어·중국어·일본어 등 **원본 영상에 실제로 있는
자막 트랙을 전부** 추출해 배운다(§2~5). **3) 역작업 학습**: 정답을 먼저
보지 않고 스스로 TC·자막을 생성한 뒤, **원본 영상에 있는 자막 하나하나를
기준으로 초안을 손으로 고친다**(`정답지-대조-진단` 스킬). **4) 반복**해서
생성기 실력을 늘린다.

**영상을 `학습완료`로 옮기는 기준은 3번이 끝난 것이다** — 3번이 끝났다는
것은:

- **TC**: 모든 영상에 있으므로 예외 없이 함. `--generate`+`--against`로
  대조해 구조적 편향을 코드로 고치는 사이클이 수렴했으면(새 버그가 더 안
  나오면) TC 학습은 된 것으로 본다.
- **자막 텍스트(SDH·번역 등)**: 원본에 실제로 존재하는 **모든 언어·모든
  방향**을 대상으로, 초안을 정답과 **큐 단위로 전부** 손교정해야 한다.
  원본에 없는 언어(예: 이 발매판에 한국어 트랙이 없다)는 요구하지 않는다 —
  없는 것을 만들어 채우지 않는다(규칙 9와 같은 정신).
  대조 통계(`--against`)만 내고 손교정을 안 했으면 **아직 안 끝난 것**이다
  — "코드 버그를 찾았다"와 "그 언어를 학습했다"는 다르다.

기준 미달인 채로 `학습완료`에 있으면 사용자가 용량 정리로 지울 위험이
있다(규칙 13 — 지우면 다시 못 한다). **애매하면 밖에 둔다.**

**"100% 일치"는 그 영상이 물리적으로 허락하는 만큼까지다**(사용자 확인,
2026-08-27). 화면 캡션(OCR 없이 못 만듦)과 영상 자체의 컨테이너 손상
(ffmpeg가 다시 튕겨 나오는 지점 — `docs/BACKLOG.md` 예능A 15·16회
사례)처럼 **코드로 고칠 수 없는 자리**는 목표 분모에서 뺀다. 이런 결손
자리가 있는 영상은 "학습완료 불가"가 아니라, 남은 대사(캡션·손상 제외)를
전부 맞추면 학습완료로 본다 — 다만 결손 근거(몇 곳, 어떤 종류)는
`rules/learned/`나 `docs/BACKLOG.md`에 반드시 남긴다. 온전한 영상과
섞이지 않게 하기 위해서다.

## 하기 전에 먼저 챙길 것

영상을 학습완료로 옮기기(그리고 나중에 지우기) **전에**, 아직 영상이 있을 때
`정답지-대조-진단` 스킬을 먼저 돌려서 생성기 자체의 코드 버그를 찾을 기회를
놓치지 않는다(규칙 13 — 영상이 없으면 이 진단은 다시 못 한다).
