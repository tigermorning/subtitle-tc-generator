# TC 작업: 사람 음성 파형으로 인점·아웃점 잡기

2026-11-12 사용자와 한 세션에서 정한 것을 모은 표준 절차다. 이 절차 밖의 방식(하드섭
화면 글자, OCR, whisper 전사, 뜻 단위 분할)으로 TC를 잡지 않는다.

## 1. 원칙 (사용자 지정)

- **TC 작업 = 사람 음성이 나오는 자리만 잡는 일.** 내용·의미 파악은 필요 없다.
- **영상 번역 자막과 SDH 모두 사람 음성만**으로 작업한다. 효과음·음악이 TC에 들어가면 안 된다(사용자 2026-11-12 정정).
- **항상 SE가 파형을 받은 뒤**, 그 SE 파형으로 인점·아웃점을 잡는다(사용자가 SE에서 보는 파형과 같은 자료).
- 대본은 **텍스트를 넣고 글자 수로 나누는 데만** 쓴다. 뜻으로 끊는 자리를 정하지 않는다.
- 결과를 뜻 단위로 끊긴 기존 자막(방송 자막, 영어 자막 트랙, 옛 수정본)과 «끊는 자리가 다르다»로
  견주지 않는다. 확인은 음성 파형과 직접 대조한다.

## 2. 규정

| 항목 | 값 | 출처 |
|---|---|---|
| 인점 | 음성 시작 전 **모눈 한 칸(0.1초 이내)** | 사용자 이미지·지적 |
| 아웃점 | 음성 끝 후 **모눈 2.5~3칸(0.25~0.3초)** | 사용자 지적(처음 이미지는 0.2~0.3초) |
| 겹칠 때 | 다음 말소리의 **인점 우선**(앞 자막 아웃점을 자름) | 사용자 이미지 |
| 최소 표시 | 아웃점 규칙보다 **Minimum Duration 우선**(발주처 규정값 — 넷플릭스 0.833초, 다음 인점은 넘지 않음) | 사용자 이미지, 규정 파일 `rules/private/netflix/common.yaml` |
| 최대 표시 | **7초를 넘으면 대본 줄 경계에서 나눔** | 사용자, 넷플릭스 규정 |
| 자막 사이 간격 | **발주처마다 다름: 0 또는 2프레임** — 작업 시작 때 묻는다 | 사용자 |
| 쉼에서 나누기 | 기본 **0.2초** 이상 쉼. 대본이 있어 글자 수가 넘치면 **0.08초** 쉼에서도 | 사용자 |
| 한 자막 최대 글자 | 영어 42×2=84, 한국어 16×2=32(`rules/private/netflix/*`) | 규정 파일 |
| 장면전환 | **SDH만** 앞뒤 최소 0.5초(그 안이면 장면전환에 붙임). **영상 번역 자막은 쓰지 않음** | 사용자 |

장면전환 세부(내가 정함, 사용자 확인 전): 인점을 장면전환에 붙이면 음성 시작을 자르게 될 때는
인점을 장면전환 0.5초 앞으로 당긴다. 다음 인점이 장면전환이면 앞 아웃점은 «장면전환 − 간격» 허용.

## 3. 작업을 시작할 때 먼저 묻는 것

1. 영상 파일과 구간(예: 02:00~05:00, 3분)
2. 종류: **SDH**인가 **영상 번역 자막**인가
3. 발주처 요청 **자막 사이 간격**: 0프레임인가 2프레임인가
4. 대본이 있는가(있으면 시각 있는 참고 자막도 — 보통 영상 안 자막 트랙)

## 4. 한 번에 돌리기

```bash
# 대본이 있으면 참고 자막을 먼저 뽑는다(일반 트랙, 있으면 SDH 트랙도)
ffmpeg -i <영상> -map 0:s:0 ref_eng.srt
ffmpeg -i <영상> -map 0:s:1 ref_eng_sdh.srt
python tools/waveform_tc/run_tc.py <영상> <시작초> <길이초> <결과폴더> <fps> <간격프레임> <sdh|translation> [<대본.txt> <참고자막.srt> <최대글자> [<SDH참고자막.srt>]]
# 예: py tools/waveform_tc/run_tc.py Toy.Story.5...mkv 300 180 "파형TC_05-08분" 24 0 translation transcript.txt ref_eng.srt 84 ref_eng_sdh.srt
```

- fps: `ffprobe -select_streams v:0 -show_entries stream=r_frame_rate`(29.97은 `30000/1001`).
- 3분 음성 분리에 CPU로 약 3분 — 백그라운드로 돌린다. 분리 결과를 다시 쓰려면 `REUSE=1`.
- 끝나면 SE4가 결과(`clip_음성만.srt`)로 다시 열린다. 사용자에게 알린다.

순서(스크립트 안):
1. 구간 원음 추출. **5.1·7.1이면 센터 채널(FC)만**(대사가 주로 있는 채널).
2. 음성 분리 `separate_onnx.py`(MDX-Net `Kim_Vocal_2.onnx`, onnxruntime CPU) → `voice_sep.wav`.
3. 사람 말소리만 `vad_mask.py`(저장소 `models/silero_vad.onnx`, 말소리 아닌 자리를 0, 앞뒤 여유 0.3초) → `voice_only.wav`.
4. `clip.mp4`(원음) + `clip_음성만.mp4`(소리를 3번 결과로) 만들기.
5. SE4를 닫고 다시 열어 **SE가 파형을 받을 때까지 기다림** → SE4 `Waveforms/*.wav`(초당 150점)를 `se_waveform.wav`로.
   소리가 전과 같으면 SE가 저장된 파형을 재사용해 새 파일이 안 생긴다 → 30초 뒤 저장된 파형 가운데 `voice_only.wav`와 가장 닮은 것(상관 0.9 이상)을 쓴다(«가장 최근»으로 고르면 이전 패스 소리를 집었다).
6. SDH면 장면전환 검출(`checker.media.detect_shot_changes`, 민감도 0.2) → `shots.json`.
7. `wave_tc.py` → 음성 조각과 인점·아웃점(`wave_only.srt`, `.json`). 5절 판정.
8. 대본이 있으면 `fill_script.py` → 텍스트 넣기·나누기·대본 없는 조각 지우기(6절).
9. 자리를 못 찾은 대본 줄이 있으면 **2차 패스**(6절) — 3·4·5·7·8을 한 번 더.
10. `clip_음성만.srt`, `clip.srt`(구간 기준), `wave_tc_원본시각.srt`(원본 시각)를 쓰고 SE4를 결과로 다시 연다.

대본이 없으면 자막 칸에 텍스트 대신 `#번호 음성 시작–끝(초)`이 들어간다.

## 5. 파형 판정 (`wave_tc.py`) — **경계는 파형으로만, VAD는 «말인가»를 가리는 데만**

사용자 2026-11-12: «파형과 소리로 음성이 시작·끝나는 부분만 파악해서 끊으면 되는데 왜 안 되나».
원인은 VAD 확률로 경계를 옮긴 것이었다 — VAD는 말이 시작되고 0.2초 안팎 뒤에야 올라가서 인점이 음성 시작보다
뒤로 갔다. 점검 도구도 같은 VAD로 재서 그 오류를 통과시켰다. 그래서 아래 원칙을 지킨다.

1. **덩어리 찾기**: SE 파형 꼭짓값이 문턱 = max(하위 20% + 20dB, 상위 1% − 35dB)를 넘는 곳. 0.2초 이상 쉬면 끊고, 0.12초보다 짧은 소리는 버린다.
2. **말인지 가리기**(`WAVE_TC_VAD_SRC` = `voice_sep.wav`): 덩어리 VAD 평균 0.5 이상이면 말.
   덩어리 앞·뒤 끝에 VAD 0.5 미만이 **0.3초 이상 이어지고 그 평균이 0.3 미만**이면(헉·덜컥 같은 비음성, 0.1 안팎)
   바뀌는 지점 ±0.15초 안에서 **파형이 가장 낮게 꺼지는 자리**로 나누고, 나눈 조각마다 다시 가린다.
   말의 첫소리는 VAD가 0.4 안팎이라 이 조건에 걸리지 않는다. 2차 패스로 되살린 대본 자리는 그대로 둔다.
3. **경계 = 보이는 파형의 첫·마지막 자리**(상위 1% − 25dB). SE 화면은 그보다 작은 소리를 거의 평평하게 그린다.
4. **끝 꼬리만** VAD로 자른다: 끝에서 VAD 0.2 미만이고 진폭이 작은(상위 1% − 15dB 아래) 꼬리. 끝에서는 VAD가 바로 떨어진다.
5. **프레임으로**: 인점 ceil((시작 − 0.1)×fps), 아웃점 ceil((끝 + 0.25)×fps).
   최소 표시 시간은 **발주처 규정값**(넷플릭스 0.833초, `WAVE_TC_MIN_DUR`) — 1.0초로 두면 아웃점이 밀린다.
   다음 인점 − 간격을 넘으면 자른다. SDH면 장면전환 규칙.

## 6. 대본 넣기 (`fill_script.py`)

1. **대본 줄의 시각**: 참고 자막(영상 안 자막 트랙)에서 같은 문장(유사도 0.8 이상)을 차례로 찾는다.
   한 참고 줄에 대본 줄이 여럿이면 시간을 나눠 준다. **자막 글자는 대본 원문만 쓴다** — 짝을 못 찾은
   참고 줄은 버린다(참고 자막에만 있는 줄을 넣으면 대본 줄이 밀려 엇갈린다). 짧은 대본 줄(8글자 미만)은
   «포함» 검사로 짝짓지 않는다. 짝이 없는 참고 줄이 대본 한 줄의 일부(12글자 이상)이면 그 대본 줄로 짝짓고,
   조각 시각에 맞춰 대본 원문을 문장부호·띄어쓰기 자리에서 나눈다. 대본 줄 시각이 구간 밖이면 넣지 않는다.
2. 대괄호 소리 표기와 `♪`는 뺀다(TC는 사람 음성만 — 번역·SDH 공통).
3. **자막에 넣기**: 대본 줄 가운데 시각에 가장 가까운 음성 조각(1.5초 안)에 넣는다.
4. **빈 조각 합치기**: 대본이 없는 조각은, 바로 옆(1초 안) 자막의 대본 줄 시각이 그 조각의 음성과
   **실제로 겹칠 때만** 합친다(여유를 두면 웃음·숨소리 조각까지 붙어 인점이 앞으로 갔다).
4-2. **SDH 소리 표기로 앞뒤 끝 자르기**: 조각의 앞 끝·뒤 끝이 소리 표기 시간 안이면 그 부분을 잘라내고,
   자른 범위 안에서 SE에 보이는 소리의 첫·마지막 자리로 다시 맞춘 뒤 인점·아웃점을 다시 잡는다(소리 표기 시각은 대략값).
4-1. **SDH 소리 표기 자리 거르기**(선택 인자 `SDH_REF.srt` = `ffmpeg -i 영상 -map 0:s:1 ref_sdh.srt`): 대괄호 표기·♪만 있는 줄의 시간 안에 절반 이상 들어가는 조각은 비음성으로 버린다. 흐느낌·웃음 같은 사람의 비음성 소리는 VAD 확률이 높게 나와 VAD로 못 거른다.
5. **대본 없는 조각은 지운다**(번역·SDH 공통). 지운 시각을 출력한다.
6. **나누기**: 한 자막이 최대 글자를 넘거나 7초를 넘으면 대본 줄 경계에서 나눈다.
   나누는 자리는 그 안의 쉼(0.08초 이상) 가운데 경계와 가장 가까운 곳, 쉼이 없으면 경계 ±0.5초 안의 가장 작은 소리.
   나눈 조각의 인점·아웃점은 같은 규칙으로 다시 잡는다.
7. **2차 패스**: 자리를 못 찾은 대본 줄(`clip_음성만.srt.unplaced.json`)이 있으면, 그 참고 자막 시각 ±0.3초를
   VAD가 지우지 않게 되살리고(`vad_mask.py ... KEEP.json`), SE 파형을 다시 받아 다시 잡는다.
   외침·배경의 작은 목소리·기계로 가공된 목소리는 분리 음성에 소리가 있어도 VAD 확률이 낮게 나올 수 있다.
   대본이 근거일 때만 되살리므로 대본 없는 소음은 그대로 걸러진다.

## 7. 자주 생기는 오류와 대처 (같은 지적을 되풀이하지 않기)

| 오류 유형 | 원인 | 대처(코드에 반영됨) |
|---|---|---|
| 비음성 소리가 TC에 들어감 | 보컬 분리만으로는 효과음·음악이 남음 | 5.1이면 센터 채널 + VAD로 말소리만 |
| 인점이 너무 앞 / 아웃점이 너무 뒤 | 시작·끝을 낮은 문턱까지 넓혀 작은 꼬리(잔향·숨)까지 음성으로 봄 | 넓히지 않고 SE에 보이는 크기로 좁힘 |
| 인점이 음성 시작보다 뒤(첫소리 잘림) | VAD 확률로 경계를 옮김(VAD는 늦게 올라감), 점검도 같은 VAD로 함 | 경계는 파형으로만, 점검도 파형으로 |
| 짧은 대사의 아웃점이 늦음 | 최소 표시 시간을 규정(0.833초)보다 긴 1.0초로 둠 | 발주처 규정값 사용 |
| 자막이 잘 안 나뉨 | 끝을 넓혀 다음 말과 붙음 | 쉼은 넓히기 전 기준 0.2초 |
| 대사 앞 짧은 소음에 인점 | 소음 조각이 대본 줄 시각과 겹쳐 합쳐짐 | VAD 확률 평균으로 거르기, 빈 조각 합치기는 실제로 겹칠 때만 |
| 대사 첫소리가 잘림 | 소음과 말소리가 한 조각인데 통째로 버림 | 조각 안 확률 0.5 이상인 부분만 남김 |
| 사람의 비음성 소리(흐느낌·웃음 등)가 대사에 붙음 | VAD 확률이 높게 나와 못 거름 | SDH 자막 트랙의 소리 표기 시간 안 조각을 버림 |
| 대본 줄이 빠짐 | VAD가 외침·작은 목소리·가공된 목소리를 지움 | 2차 패스로 대본 자리 소리를 되살림 |
| 같은 대본이 두 번 들어감, 대본 줄이 엇갈려 들어감 | 참고 자막에만 있는 줄을 글자로 넣음 | 자막 글자는 대본 원문만, 짝 없는 참고 줄은 버림 |
| 긴 대본 한 줄이 통째로 빠지거나 안 나뉨 | 참고 자막이 그 줄을 여러 조각으로 나눔 | 조각을 그 대본 줄에 짝짓고 원문을 조각 자리에서 나눔 |
| 앞뒤 구간의 대사가 들어감 | 구간 경계 근처 대본 줄을 가장 가까운 자막에 넣음 | 시각이 구간 밖인 대본 줄은 넣지 않음 |
| 7초 넘는 자막 | 글자 수 기준만으로는 안 나뉨 | 7초 넘으면 대본 줄 경계에서 나눔 |
| 대사 앞뒤의 사람 비음성 소리(헉·외침·끙)까지 TC에 들어감 | 한 조각에 말과 비음성이 붙음, 조각 평균만 봄 | 조각 앞뒤 끝을 VAD·SDH 소리 표기로 잘라냄, 전수 점검 |
| 다시 돌릴 때 엉뚱한 파형을 씀 | SE가 저장된 파형을 재사용, 최근 파일이 다른 소리 | 지금 소리와 가장 닮은 파형을 고름 |

새 지적을 받으면 대사·작품 이름 같은 구체적 예시가 아니라 이 표처럼 **오류 유형·원인·대처**로 일반화해 적는다.
대본 글자와 들리는 말이 다를 때 글자를 고치는 것은 결과 파일에서 하고, 스킬에는 적지 않는다.

  자막마다 **파형**(보이는 크기)으로 음성 시작·끝을 다시 재서(VAD로 재지 않는다 — 같은 VAD로 재면 VAD 오류를 못 잡는다)
  인점 0~0.1초 앞, 아웃점 0.25~0.3초 뒤(다음 인점·최소 표시 예외, 측정 오차 0.01초)인지, 인점 바로 앞·아웃점 바로 뒤에

## 12. 영상 번역 자막이면 늘 거치는 단계: 글자 전수조사 → 1차 번역 → SE 번역 칸 (사용자 2026-11-12)

TC가 끝난 뒤, 영상 번역 자막 작업이면 사용자에게 넘기기 전에 반드시 아래를 한다.

1. **글자 전수조사**: 자막마다 실제로 들리는 말과 대본 글자가 맞는지 본다.
   - 분리 음성을 받아쓴다(이 PC는 faster-whisper가 막혀 ffmpeg whisper 필터를 쓴다. 모델 `D:\자막TC생성기\userdata\models\ggml-large-v3-turbo.bin`,
     경로에 한글이 있으면 필터가 못 읽으니 모델 폴더에서 상대 경로로 돌린다):
     `ffmpeg -i <폴더>/voice_sep.wav -af "aresample=16000,whisper=model=ggml-large-v3-turbo.bin:language=en:queue=10:destination=asr.srt:format=srt" -f null -`
   - `tools/waveform_tc/check_text.py clip_음성만.srt asr_voice.srt text_check.tsv` → 유사도 0.6 미만을 하나씩 본다.
     받아쓰기 한 구간이 자막 여러 개에 걸치면 유사도가 낮게 나오므로, 자막과 받아쓰기를 **시간순으로 나란히** 놓고 판단한다.
   - 받아쓰기는 «어느 대본 줄이 그 자리인지» 판단하는 데만 쓴다. 자막 글자는 대본 원문을 쓰고, TC는 바꾸지 않는다.
   - 대본 글자와 받아쓰기가 다르고 사용자가 들은 말과도 다르면 사용자에게 알린다(사용자 판단이 우선).
2. **1차 번역**: 자막마다 한국어로 옮긴다(`ko_draft.tsv` 번호·글자 → `clip_음성만.ko.srt`, TC는 원문과 같게).
   - 기준: `rules/private/se-guide/` 영상 번역 규칙과 발주처 프로파일(넷플릭스: 한 줄 16자·2줄, 마침표 없음,
     문장 끝 쉼표 없음, 말줄임표 «…», 두 화자는 «- »), 프로젝트 CLAUDE.md 2절(의역, 불가감·불가증).
   - `python -m checker <ko.srt> -p <발주처> -l ko -k translation`으로 검사한다.
   - 한 칸에 화자가 셋 이상이거나 담을 수 없는 말이 있으면 억지로 줄이지 말고 «TC를 나눠야 함»으로 보고한다.
3. **SE 번역 칸으로 열기**: `python tools/waveform_tc/se_open_pair.py <ko.srt> <원문.srt> <clip_음성만.mp4>`
   — SE4 최근 파일에 원문을 달아 열어 번역 칸(원문 열 + 번역 열)이 보이게 한다. 영상은 **음성만판**(TC를 잡은 파형과 같게 —
   원음판을 붙이면 파형이 달라 보여 TC를 잘못 판단한다). SE가 저장을 물으면 저장하지 않고 닫는다(사용자 지정).

## 13. 들을 수 없는 자리는 단어 시각으로 확인한다 (2026-11-12)

Claude는 소리를 직접 듣지 못한다. VAD가 못 가리는 자리(외침·웃음과 말이 붙은 덩어리, 2차 패스로 되살린 자막)는
**단어 단위 받아쓰기**로 어느 소리가 어떤 단어인지 확인한 뒤 경계를 정한다.
- 도구: SE가 받아 둔 `%APPDATA%\Subtitle Edit\SpeechToText\Cpp\whisper-cli.exe`(앱 제어에 안 막힘).
  모델 경로에 한글이 있으면 못 읽으니 **모델 폴더(`D:\자막TC생성기\userdata\models`)에서 상대 경로로** 돌린다.
  `whisper-cli -m ggml-large-v3-turbo.bin -f seg.wav -l en -ml 1 -sow -ojf -of seg` → `seg.json`의 단어별 시각·확신도(p).
- 확신도가 낮은 단어(예: 0.12)는 앞뒤 소리를 묶은 것이라 믿지 않는다. 확신도 높은 단어의 시작이 덩어리 경계 근처면 그 덩어리를 그 대사로 본다.
- 외침은 단어로 안 나올 수 있다 — 그때는 대본 순서와 파형으로 정하고 «귀로 확인»에 남긴다.

## 14. 정확도는 «정답 TC»로만 잰다 (2026-11-12)

- 점검 도구(`check_tc.py`)의 «문제 0개»는 우리 규칙으로 잰 결과일 뿐, 정확도가 아니다. 정확도를 말하지 않는다.
- 사용자가 한 구간을 SE에서 직접 듣고 고쳐 저장하면 그것을 정답으로 삼아, 규칙을 바꿀 때마다
  «인점·아웃점이 정답과 N프레임 안에 맞는 자막 비율»을 비교한다.
- 검토 중인 규칙 후보(정답으로 효과를 재기 전에는 넣지 않음): 보이는 크기(상위 1% − 25dB)를 0.1초 이상 넘는 소리가
  없는 조각은 음성으로 보지 않는다(사용자: «소리가 매우 작은 것은 음성이 아닐 가능성»).
