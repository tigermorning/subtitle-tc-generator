# 플리토 자가교정(Judge & Refine) 파이프라인

이 저장소의 자막 번역 작업은 **번역을 만드는 것으로 끝나지 않는다**. 만든 자막은 반드시
4차원 Judge 검수를 거치고, 실패한 부분은 Judge의 reasoning을 근거로 최대 2회 자가교정
(Refine)하며, 그래도 통과하지 못하면 사람 검토(human_review)로 승격된다.

설계의 근거와 원문 분석은 `docs/BENCHMARK_FLITTO_PIPELINE.md`가 담당한다. 이 스킬은
실전 절차를 다룬다.

## 선행 원칙 — 헌법이 이 루프보다 위다

- 헌법 1조: TC는 Refine 대상이 아니다. `--lock-timecodes` 파일의 인점·아웃점은 어떤
  차원의 점수로도 움직일 수 없다. tc_sync가 낮으면 **텍스트를 압축하는 방향**으로만 고친다.
- 헌법 2조: Refine은 창작이 아니다. 원문(원어 스크립트)에 근거 없는 내용은 수정으로도
  추가할 수 없다(불가증). 글자 수를 줄이는 핑계로 핵심 정보를 빼는 것도 금지(불가감).
- 헌법 5조: Judge 점수는 사람을 대신하지 않는다. 최종 납품 기준은 사람이며, Judge의 역할은
  사람이 볼 지점과 근거를 정확히 남기는 것이다.

## 작업 절차

### 1. Generate — 번역 생성

평소대로 만든다. 헌법 3조의 표준 파이프라인 순서를 따르고, 원어 스크립트와 TC를 입력으로
한국어 번역 자막을 출력한다. 이 단계를 끝낸 자막은 **초안**이다.

### 2. Judge — 4차원 검수

`prompts/subtitle_judge.md` 템플릿을 사용한다. 입력은 ① 대상 자막(원어+한국어 쌍 또는
한국어+원문 스크립트), ② 원어 스크립트(검증 근거), ③ 적용되는 발주처 프로파일(CPS·글자 수
규정). Judge가 반환할 것:

```json
{
  "scores": [
    {"dimension": "faithfulness",   "score": 0, "reasoning": "…"},
    {"dimension": "tc_sync",        "score": 0, "reasoning": "…"},
    {"dimension": "readability_cps","score": 0, "reasoning": "…"},
    {"dimension": "naturalness",    "score": 0, "reasoning": "…"}
  ],
  "verdict": "pass | fail | human_review"
}
```

차원별 채점 기준(0–10점):

| 차원 | 기준 | 즉시 탈락(0점) 조건 |
|---|---|---|
| faithfulness | 원문 불가감·불가증 기반 정합성 (헌법 2조) | 임의 창작, 원문 미지원 내용 생성, 핵심 정보 누락 |
| tc_sync | 인점·아웃점 싱크, 최소 간격·표시 시간·컷 경계 (헌법 1조) | `--lock-timecodes` TC 변조, 자막 겹침 |
| readability_cps | 줄당 글자 수, 줄바꿈 호흡, CPS 제약 (헌법 3조) | 발주처 규정 명백 초과 |
| naturalness | 자연스러운 한국어 구어체 의역, 번역투 배제 | 외국어 담화표지·원어 잔어 잔류 |

판정 규칙:

- **모든 차원 ≥ 7.0 → `pass`** — 사람 최종 검수로 넘긴다(자동 납품이 아니다).
- **하나라도 < 4.0 → `fail`** — Refine 대상.
- **그 외(4.0–6.9) → `human_review`** — 루프를 돌지 않고 바로 사람에게 보인다. 애매한
  중간 점수로 반복 수정을 시도해 기록을 더럽히지 않는다.

tc_sync는 점수화 전에 먼저 확인한다: TC 위반이 발견되면 그 시점에서 fail이고, 나머지
차원의 점수는 사람이 문제를 볼 수 있게 **참고 기록으로만** 남긴다.

### 3. Refine — Judge 피드백 자가교정 (최대 2회)

`prompts/subtitle_refine.md` 템플릿을 사용한다. 절차:

1. Judge가 준 차원별 점수와 reasoning을 전부 읽고 저점의 근본 원인을 특정한다
   (오역 / 정보 누락 / TC 위반 / CPS 초과 / 번역투).
2. 특정된 원인에 대응하는 부분만 고친다. 점수가 높았던 부분은 건드리지 않는다.
3. 수정 결과를 원어 스크립트로 다시 검증한다 — Refine이 새 사실을 만들지 않았는지.
4. Judge 재평가로 돌아간다.

한도와 종료:

- **최대 2회**. 각 회차마다 재평가를 거치고, 모든 차원이 ≥ 7.0이면 즉시 종료한다.
- **2회 실패 시 `human_review`** — 더 돌리지 않는다. 같은 차원에서 점수가 오르지 않는다는
  것은 자가교정으로 풀 문제가 아니라는 신호다(원문 자체의 모호함, 규정 갈등 등).
- **타겟 언어 락(STRICT)**: 수정 결과는 전부 한국어다. 외국어 담화표지(예: 한국어에
  首先/其次/最后, first/second 삽입), 원어 잔어를 새로 넣지 않는다. 나열은 한국어의
  자연스러운 연결어(첫째/둘째/셋째)로 쓴다.
- **TC 불변**: Refine은 텍스트만 바꾼다. 인점·아웃점은 append 확정 값 그대로다
  (`update`는 텍스트 소급 교정이지 타임스탬프 재배치가 아니다 — rtt_sdk의 상태 모델과 같다).

### 4. 기록

각 Judge 호출의 JSON(점수+reasoning)과 각 Refine 회차의 변경 요약을 작업 산출물로 남긴다.
사람 검토자는 pass를 믿지 말고 이 기록을 보고 검증한다.

## 자막 상태 머신 — 언제 Judge·Refine을 도는가

rtt_sdk(`flitto/rtt_sdk`, `chat-guest`의 `listType`)에서 이식한 상태 모델:

```
realtime (임시) ──▶ append (확정) ──▶ update (문맥 소급 교정)
```

- **realtime**: 원어 발화 경계가 확정되기 전. 한국어 초안이 있어도 확정 아님.
- **append**: 발화·TC 확정. 이 시점부터 Judge 후보가 된다.
- **update**: 이후 문맥이 붙은 뒤의 소급 교정. **Judge·Refine 루프는 이 update 단계에서
  돈다.** 한 칸을 그 칸만 보고 pass하지 않는다 — 대명사 처리, 호칭 일관성, 번역투는 뒤
  문맥이 있어야 잡힌다.

## 프롬프트 템플릿

- Judge: `prompts/subtitle_judge.md` (이 스킬 폴더 안)
- Refine: `prompts/subtitle_refine.md` (이 스킬 폴더 안)

템플릿은 그대로 출력 포맷과 규칙을 강제하는 시스템 프롬프트로 쓴다. 모델이 바뀌어도
루브릭·임계치·언어 락 조항은 바꾸지 않는다 — 이 프로젝트의 표준이기 때문이다.

## 함정 (플리토가 명시하고, 이 프로젝트도 적용한다)

- **자기 채점 편향**: 생성에 쓴 모델·세션이 곧바로 Judge가 되지 않게 분리한다. 불가능하면
  최소한 생성 직후 이어서 자기 출력을 스스로 채점하는 일을 피하고, reasoning 필수 채점으로
  점수의 근거를 남겨 사람이 검증 가능하게 한다.
- **점수 목적화**: "점수를 올리기 위한 수정"은 금지다. 목표는 헌법 준수 자막이지 7.0 이상의
  숫자가 아니다. Judge는 그 왜곡을 잡아야 한다.
- **verdict 오남용**: `human_review`는 실패 은폐가 아니라 정상 출력이다. 애매하면
  human_review로 보내는 것이 이 파이프라인의 올바른 실패 방향이다.
