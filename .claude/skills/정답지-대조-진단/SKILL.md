# 정답지 대조 진단

`CLAUDE.md` 규칙 13을 코드화한 것이다. **정답지가 있는 것은 드문 기회다** — 실전
작업에는 정답이 없다. 이 진단의 목적은 "내 판단력을 연습"하는 게 아니라,
**정답 없는 실전에서도 통하는 도구 자체를 검증하고 고치는 것**이다.

## 언제 쓰나

- `정답지-학습` 스킬로 정답 srt를 확정한 영상이 아직 삭제되지 않았을 때
- **영상을 `학습완료`에서 지우기 전에 반드시 먼저 돈다** — 영상(음성)이 없으면
  전사를 다시 못 하므로 이 진단은 다시 할 수 없다. 이미 늦은 사례: 드라마A
  Texas, 예능B, 영화A, 드라마C(영상이 이미 삭제됨).

## 절차

### 1. 초안을 만든다 (정답지는 보지 않는다)

```bash
python -m checker --generate --video <영상> --whisper-lang <ko|en|...> \
  -p <platform> -l <lang> -k <sdh|translation> -o <초안.srt>
```

- 번역이 필요 없는 SDH(원어=자막 언어)면 `--translate` 없이 돌린다 — 더 단순하고
  빠르다.
- 공식 프로파일이 없는 발주처(예: amazon)는 구조가 비슷한 공식 프로파일(예:
  netflix)을 임시로 써도 된다 — 이 진단의 목적은 규정 준수가 아니라 생성기 자체의
  스포팅·분할 로직 검증이다.

### 2. 정답과 대조한다

```bash
python -m checker <초안.srt> --against <정답.srt> --eval-json <out.json>
```

인점·아웃점 편향(가운데값·흩어짐·최악), 짝지음/빠뜨림/군더더기 개수, "가장 많이
어긋난 자막" 목록을 본다.

### 3. 개별 오차와 구조적 편향을 구분한다

- **한 편에서만, 몇 개만 어긋나는 것**은 노이즈다 — 코드를 고치지 않는다.
- **여러 회차·여러 작품·여러 장르에서 같은 방향으로 반복되는 것**만 코드 버그
  후보다. 최소 2편 이상에서 같은 패턴을 확인하고 고친다(규칙 12의 "몇 편 몇 개"
  증거 기준과 같은 정신).
- 의심 가는 자리를 직접 원문(정답 srt)과 초안에서 같은 시간대를 찾아 대조해
  본다 — duration이 `833/2000/4000/7000ms`처럼 딱 떨어지면 실제 스포팅 값이
  아니라 **어딘가의 상한·하한에 부딪혀 멈춘 값**이라는 신호다
  (`checker/timing.py`의 `converge()` max_duration_ms 클립처럼).

### 4. 코드를 고친다 (정답지·학습 자료는 절대 고치지 않는다)

- 고칠 대상은 `checker/`의 코드다. 정답지를 원인 규명 없이 재구성하거나, 학습
  자료(`rules/learned/`)에 이 결과를 섞지 않는다 — 이 진단은 별개 트랙이다.
- 고치고 나서 `tests/run_tests.py`로 회귀가 없는지 반드시 확인한다.
- **모든 편향이 코드로 완전히 고쳐지진 않는다.** 예: whisper가 노래·박수·비대사
  발성을 대사처럼 전사하는 문제(2026-08-26, 예능A·영화D·영화F
  세 작품에서 공통 확인)는 스포팅 코드 하나로 못 고친다 — 별도 기능(오디오가
  대사인지 아닌지 판별)이 필요한 규모면 `docs/BACKLOG.md`에 남기고 넘어간다.

### 5. 고침을 검증한다

같은 영상으로 다시 `--generate`+`--against`를 돌려, 지목했던 구체적인 사례
(타임스탬프 하나를 콕 짚어서)가 실제로 바뀌었는지 확인한다. **전체 평균이
좋아졌다고 성급히 말하지 않는다** — whisper 전사 자체가 GPU에서 매번 100% 같지
않고, 다른 원인(노래·효과음)이 더 크게 끼어 있으면 평균은 안 움직일 수 있다.
평균과 별개로, 고친 그 메커니즘이 실제로 고쳐졌는지를 개별 사례로 증명한다.
